매일 자정 집 PC의 예약 작업이 이 절차를 돈다. 손으로 `/하자보완` 을 쳐도 같다. 문체·증거·판례의 하자가 다음 날로 넘어가지 않게 그날 손댄 사건마다 최종 관문(`공통/scripts/final_check.py`)을 돌려 막힌 곳을 보고하고, 그날 담당자가 지적한 것이 지침과 검사로 옮겨졌는지 보아 빈틈이 있으면 시스템 파일을 고친다. 2026. 11. 2. 담당 노무사 지시("모든 자동화 시스템에 최종 재검토 완결성 100%로 만들어야 하고, 자동화 시스템도 … 매일 자정에 자체 하자보완 시스템 도입해야 할듯", "백그라운드작업 활용하면 사용량 누수가 너무 심하니 직접 하는걸로"). 그날 GGM 사 제6호증 3면을 첫 면만 읽어 놓친 일이 인용 대조·맞대기·통독을 모두 지나간 뒤였다.

인자: $ARGUMENTS

**하위 작업·백그라운드를 띄우지 않고 이 세션이 직접 한다.** 스크립트 검사를 먼저 돌리고, 모델이 원문을 읽는 것은 막힘과 지적이 가리키는 곳으로 좁힌다(사용량). 클라우드 세션(claude.ai/code)에는 사건 폴더가 없으므로 2.와 4.의 시스템 점검만 한다.

## 기록

`공통/사건/_하자보완기록.md` 에 적는다. `사건/` 아래라 git 에 올라가지 않고 OneDrive 로 두 PC가 함께 본다. 날짜별 관문 결과 전문은 `공통/사건/_하자보완/{날짜}_관문.md` 에 둔다.

```
마지막 확인: 2026-11-03 00:04

| 날짜 | 시스템 시험 | 사건(막힘) | 지적(이미 반영/새로 고침/정할 것/뺌) | 고친 시스템 파일·커밋 |
```

## 순서

1. **범위를 정한다.** 인자가 없으면 기록의 '마지막 확인' 10분 전부터 지금까지이다. 기록이 없으면 지난 26시간으로 하고 기록을 만든다. 자정을 놓쳐 다음에 앱을 켤 때 몰아 돌아도 이 기준이라 빠지는 날이 없다.
2. **시스템을 시험한다.** 시스템 파일은 시작 훅이 받아 왔다(`receive.py --auto`). `python -B -m unittest discover -s 공통/tests` 와 `python -B 공통/scripts/system.py check` 를 돌린다. 실패하면 원인을 찾아 고치고 다시 돌려 통과시킨 뒤 `공통/운영.md` '시스템 파일 올리기'대로 올린다. 시험을 끄거나 건너뛰거나 기대값을 실패에 맞춰 바꾸지 않는다.
3. **그날 손댄 사건에 최종 관문을 돌린다.** `python -B 공통/scripts/final_check.py --최근 {범위 시간} --out "공통/사건/_하자보완/{날짜}_관문.md"` 가 그 시간 안에 파일이 바뀐 서면·검토의견·계산 사건마다 문체·판례(대조·판결문 PDF·사람 판정·검색 기록·찾은 판례 다시 훑기)·증거(전 면 읽기·쟁점 낱말·증거 인용 판정·상대 서면 맞대기)·의뢰인 주장 반영·DOCX 최신 여부·예상 질의답변을 본다. 머리에 본 판과 고친 때, 이번 범위에 고쳤는지, 넘긴 판일 수 있는지를 적는다. 관문은 사건 폴더의 파일을 고치지 않는다.
   - **산출물과 사건 기록은 고치지 않는다.** 서면초안·docx·검토의견서·회신초안·제출 묶음·호증목록·사건상태와 읽기 기록·대조표·판정 칸이 그렇다. 그 사건을 맡은 세션이 원문을 읽고 담당자와 함께 할 일이고, 밤에 대신 채우면 읽지 않은 채 칸만 차기 때문이다.
   - 막힘을 사건마다 보고로 옮긴다. `출력/` 에 docx 나 `출력/제출/` 이 이미 있는 사건은 넘긴 판일 수 있으므로 보고 첫머리에 올린다.
   - 막힘이 지침·스크립트의 빈틈 때문이면(관문이 잘못 막았다, 다른 폴더에는 같은 검사가 없다, 검사가 없어 글로만 남았다) 4.의 '고친다'처럼 시스템을 고친다.
4. **그날의 지적을 본다.**
   - 모은다: `공통/사건/_지적기록/*.jsonl` 에서 범위 안의 줄(두 PC의 모든 세션에서 담당자가 결과를 지적한 것으로 보이는 메시지를 `case_watch.py` 훅이 적는다)과, `git log --since` 의 커밋(두 PC와 클라우드 세션에서 올린 지침 변경. 커밋 글에 담당자 말이 있다). 잡담과 단순 질문은 빼고 수만 센다.
   - 가른다: 지적마다 (가) 같은 날 지침·검사로 옮겨졌는가(커밋과 지침에서 그 말과 날짜를 찾는다), (나) 옮겨졌다면 같은 유형이 다른 폴더·명령에도 있는가(서면에서 고친 증거 읽기를 검토의견·손배계산 자료 읽기에도 해야 하는가), (다) 기계로 잡을 수 있는 것인데 글로만 남았는가, (라) 고친 지침이 다른 지침과 부딪치지 않는가.
   - 고친다: 옮겨지지 않았거나 넓혀야 하거나 검사로 만들 수 있는 것은 지금 시스템 파일을 고친다. 지침은 해당 부분만 고치고(파일 전체를 새로 쓰지 않는다), 검사는 스크립트와 시험을 함께 만들어 `final_check.py` 에 잇는다. 같은 규칙을 두 벌로 두지 않고, 담당자 말과 날짜를 붙인다. 시험과 `system.py check` 를 통과시켜 올린다.
   - 사건 문언은 시스템 파일에 옮기지 않는다. '스캔 호증의 쟁점 문구'처럼 일반화해 적는다(루트 `CLAUDE.md` Microsoft 365 규칙, 2026. 11. 2. 지침 정리).
   - 담당자가 정할 방향(두 지침이 부딪침, 업무 방식이 바뀜)은 고치지 않고 보고의 '정할 것'에 둔다.
5. **기록을 고치고 보고한다.** 기록의 표와 '마지막 확인'을 고친다. 보고는 한국어로 짧게 아래 순서로 쓴다.
   - 확인한 범위: 시스템 시험 n개(실패 n, 고침 n), 사건 n건, 지적 n건(뺀 것 n)
   - 넘긴 판일 수 있는 사건의 막힘, 그다음 나머지 사건의 막힘(사건마다 막힌 검사와 한 줄)
   - 지적: 이미 반영 n, 오늘 새로 고친 것(파일과 한 줄), 정할 것
   - 고친 시스템 파일과 커밋

   예약 실행이면 보고를 마친 뒤 `set_remote_control` 로 이 세션의 원격 제어를 켜 휴대폰 목록에서 보고가 보이게 한다.

## 하지 않는 것

- 하위 작업·백그라운드를 띄우지 않는다.
- 산출물·사건 기록·읽기 기록·판정 칸을 고치거나 대신 채우지 않는다.
- 메일·팀즈에 쓰지 않는다. 전자소송에 들어가지 않는다.
- 시험을 끄거나 건너뛰어 통과시키지 않는다.

## 예약 작업 만들기(집 PC에서 한 번)

`공통/운영.md` '새 세션 열기' 1.·4.처럼 `create_scheduled_task` 로 만든다.

- 이름 `self-audit`, 폴더는 저장소 루트, 일정은 매일 0:00(`0 0 * * *`), `notifyOnCompletion` 을 켠다. 저녁 8시의 `mail-sync` 와 같은 집 PC에 둔다.
- **예약 작업은 한 PC에만 둔다.** 두 PC에 두면 같은 지적을 두 번 고친다.
- 지시문: "`.claude/commands/하자보완.md` 절차대로 마지막 확인 이후를 점검하라. 담당자는 자리에 없다. 보고는 한국어로 한다."
- 결과 문구에서 권한 모드를 보고, 기본 모드로 저장되었으면 자동 모드로 바꿔 달라고 담당자에게 한 줄로 알린다. 만든 뒤 '지금 실행'으로 한 번 돌려, 승인 창이 뜨는 도구를 '항상 허용'으로 남긴다.
- 노력 수준은 프로젝트 설정으로 최대로 돈다(`공통/운영.md` '새 세션 열기' 5.).
- 앱이 켜져 있고 PC가 깨어 있을 때만 돈다. 자정에 PC가 꺼져 있으면 다음에 앱을 켤 때 한 번 몰아 돈다.
