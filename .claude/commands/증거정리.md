운영 기준: `공통/운영.md`를 먼저 적용한다. 사건 작업의 최초 전체 검토와 후속 변경분 검토는 `공통/사건상태.md`로 구분한다. 사건 자료를 처음부터 모두 읽는 것은 최초 분석 또는 상태 미검증 시의 기준이며, 검증된 후속 작업은 변경분과 인용 원문을 확인한다. 보완 메모는 MD 하단에만 두고 DOCX 본문에는 넣지 않는다.

대상: $ARGUMENTS


사건 폴더는 `4_서면작성/사건/{사건명}` 이다. 사용자가 사건명만 적으면 그 아래에서 찾는다.
작업 지침은 `4_서면작성/CLAUDE.md` 를 읽고 따른다.

다음 절차를 순서대로 실행해줘:

1. 사용자가 지정한 경로(예: 4_서면작성/사건/{사건명}/라운드N/)의
   우리증거/ 폴더와 상대증거/ 폴더 안의 파일 목록을 확인해줘.

2. 4_서면작성/사건/{사건명}/증거관리/우리호증목록.md 를 열어서
   현재까지 부여된 마지막 호증번호를 확인해줘.
   상대호증목록.md 도 동일하게 확인해줘.

3. 우리증거/ 폴더 안의 파일 중 아직 호증번호가 없는 파일에
   마지막 호증번호 다음 번호부터 순서대로 부여하고
   증거관리/우리호증목록.md 에 아래 형식으로 추가해줘:

   | 호증번호 | 파일명 | 내용 요약 | 관련 쟁점 | 라운드 |

   번호 순서는 서면 본문에서 처음 인용할 순서를 따른다(`4_서면작성/skills/노동서면작성/references/서면별-구조.md`
   '입증방법 표기'). `/서면` 안에서 초안 전에 수행하면 프레임 목차와 사실관계 흐름으로 인용 순서를 가늠해
   매기고, 초안을 쓴 뒤 어긋나면 `/서면` 7-1단계에서 미제출 호증만 다시 맞춘다. 이전 라운드 번호와
   이미 제출한 호증은 바꾸지 않는다.

   내용 요약은 파일을 직접 읽어서 한 줄로 작성해줘.
   이미지/PDF라서 읽기 어려우면 파일명 기준으로 요약하고
   [내용 확인 필요] 태그를 붙여줘.
   관련 쟁점은 절차적 부당성/실체적 부당성/양정/인과관계 등
   해당 사건의 핵심 쟁점 중 어디에 해당하는지 판단해줘.

   [특수 케이스 처리]
   - 합본 PDF(서면+증거가 한 파일): 내용을 읽어서 서면 부분과 증거 부분을 구분하고,
     증거 부분만 호증목록에 등록. 파일명 뒤에 (합본) 표시.
   - 증거 여러 개가 한 PDF에 묶인 경우: 각 증거의 페이지 범위를 파악해서
     호증목록에 파일명(p.시작-끝) 형식으로 페이지 범위를 함께 기록.
     물리적 파일 분리는 하지 않음. **경계는 아래 '호증 경계 확정' 규칙을 따른다.**
   - 파일명에 이미 호증번호가 있는 경우(예: 을제1호증_근로계약서.pdf):
     기존 번호를 그대로 인식하고 새 번호 부여하지 않음.
     **다만 파일명의 번호가 그 파일의 내용과 맞는지는 별도로 확인한다.**
   - 파일 내용을 읽기 어려운 경우(스캔본 이미지 등):
     **텍스트 추출이 안 되면 페이지를 이미지로 렌더링해서 눈으로 읽는다.**
     `[내용 확인 필요]` 는 렌더링해도 판독이 안 될 때만 쓰고, 그 상태로 편철하지 않는다.

## 호증 경계 확정과 편철 검증 (반드시)

2026. 9. 16. 이케아 사건에서 합본 PDF를 호증별로 나눌 때 **각 호증의 도장이 찍힌
첫 장이 앞 호증 파일의 끝에 붙는 경계 어긋남**이 있었고, 그 파일을 그대로 갑호증으로
편철해 표제와 내용이 다른 증거 4건이 법원에 제출되었다. 한 번 밀리면 그 뒤 호증이
줄줄이 밀리므로 아래를 지킨다.

**1. 경계는 도장 위치로 정한다.** 페이지 수나 분리 목록의 추정 범위로 정하지 않는다.
각 호증의 첫 장에 찍힌 호증 도장을 찾아 그 면부터 다음 도장 직전 면까지를 한 호증으로
본다. 도장이 없는 호증(표지 라벨이 없는 원본)은 그 사실을 호증목록 비고에 적는다.

**2. 분리·편철 뒤에는 전수 검증한다.** 표본 검사로 끝내지 않는다.

```powershell
python 4_서면작성/scripts/evidence_check.py stamp "{사건}/라운드N/우리증거"
python 4_서면작성/scripts/evidence_check.py trace "{원본폴더}" "{편철폴더}"
python 4_서면작성/scripts/evidence_check.py sheet "{편철폴더}" --out "{사건}/증거관리/증거확인.png"
```

`stamp` 로 1면에 도장이 없는 파일을 걸러 내고, `trace` 로 편철본이 원본 한 파일에서
연속으로 왔는지 보고, `sheet` 로 만든 이미지의 **모든 칸을 눈으로 본다.** 도장 검출은
오탐·누락이 있으므로 `stamp` 결과만으로 끝내지 않는다.

**대조는 렌더 지문으로 한다.** `trace` 는 면을 그림으로 그려 그 픽셀로 지문을 만들어
원본 면과 편철 면을 맞춘다. **PDF 내부 참조번호(xref)나 `get_images()` 결과를 지문에
섞지 않는다.** 면을 새 파일로 떼어내면 그 번호가 다시 매겨져 같은 면이 다른 것으로
나온다. 2026. 9. 22. GGM 정직 3월 사건에서 참조번호를 섞은 즉석 스크립트가 멀쩡한
83면을 전부 불일치로 보고했다. **직접 대조 코드를 새로 쓰지 말고 `trace` 를 쓴다.**

`trace` 는 편철 결과를 원본 쪽에서도 본다. 끝에 나오는 세 수치를 함께 확인한다.

| 수치 | 뜻과 할 일 |
|---|---|
| 미사용 원본 면 | 편철에 한 번도 안 쓰인 면. **뺀 이유를 호증목록 비고에 적는다.** 빠뜨린 것이면 호증을 더 만든다. 중복 편철된 사본이거나 제출 보류한 자료면 그렇게 적는다 |
| 중복 사용 | 같은 원본 면이 두 호증에 들어간 것. 의도한 것이 아니면 한쪽을 뺀다 |
| 원본에 없는 편철 면 | 원본과 맞지 않는 면. 0이 아니면 다른 자료가 섞였거나 편집된 것이므로 그 면을 연다 |

위 표와 도구 끝줄의 '(원본없음)은 신규 서증이다'는 원본→편철 대조에서의 뜻이다. 원본이나 편철 폴더
경로를 잘못 주어도 '원본 0면'으로 끝날 수 있으므로, 원본 면수가 0이면 경로부터 확인한다.

**제출 묶음을 만든 뒤에는 편철본과 제출본이 같은지도 대조한다.** `trace` 는 렌더한 픽셀이 같은 면만
짝짓는다. 변환 없이 복사한 파일은 두 폴더를 각각 `trace` 의 원본·대상으로 주면 면마다 짝이 맞는지 나온다.
A4 맞춤·회전처럼 변환을 거친 면은 이 대조에서 '(원본없음)'과 '미사용 원본 면'으로 나오는 것이 정상이므로
그것만으로 다른 자료가 섞였다고 보지 않는다. 변환한 파일은 ① 호증별 파일과 면수가 편철본과 같은지 보고,
② 모든 면을 이미지로 만들어 눈으로 본다.

```powershell
python 4_서면작성/scripts/evidence_check.py sheet "{사건}/라운드N/출력/제출/증거" --all-pages --out "{사건}/증거관리/제출본확인.png"
```

**3. 경계 어긋남을 하나라도 찾으면 그 구간 전체를 다시 본다.** 해당 파일만 고치지
않는다. 이케아 사건에서 사 제64·65호증의 어긋남을 발견하고도 그 구간만 손보는 바람에
앞의 사 제61~63호증과 뒤의 사 제67호증의1·2가 밀린 채로 남았다.

**4. 대응관계는 근거를 적는다.** 원 호증과 새 호증의 대응을 호증목록에 적을 때
추정으로 쓰지 않는다. 도장·내용으로 확인한 뒤, 가능하면 **이미 제출한 서면이 그 호증을
어떤 내용으로 인용했는지** 교차 대조한다. 이케아 사건에서는 우리 재심이유서(4)가
"사 제62호증 = 접속기록 수집·이용 동의", "사 제63호증 = 동원홈푸드 진술"로 인용하고
있어 대조가 가능했는데도 반대로 적힌 기재가 그대로 남아 소장까지 전파되었다.

**5. 검증하지 않은 가정을 목록에 적지 않는다.** "이미 다른 호증으로 편철되어 있으므로
중복 제외" 같은 문장은 그 호증을 직접 열어 확인한 뒤에만 쓴다.

**6. 이미 제출한 증거에서 오류를 찾으면 가지번호로 추가 제출한다.** 종전 호증을 그대로
두고 같은 표제의 완전본을 `제N호증의2` 로 낸다. 종전 편철본은 지우지 않고 남긴다.

4. 상대증거/ 폴더도 동일하게 처리해서
   증거관리/상대호증목록.md 에 추가해줘.
   단, 상대 호증 번호 체계는 별도로 관리한다. 어느 부호를 쓰는지는 우리가 어느 쪽을 대리하는지와
   절차에 따라 갈리므로, 프레임 표지의 당사자 표시와 기존 호증목록·이전 서면의 입증방법을 먼저 보고 정한다.
   - 노동위원회: 근로자 쪽 노 제O호증, 사용자 쪽 사 제O호증
   - 소송: 원고 갑 제O호증, 피고 을 제O호증. 우리가 피고보조참가인이면 을나 제O호증을 쓴다
     (`4_서면작성/templates/표준양식.docx` 입증방법이 이 표기이다)
   - 아래 5의 파일명 예시(우리 노·상대 사)는 우리가 노동위원회에서 근로자 쪽인 경우이다

5. 새로 추가된 파일의 이름을 아래 형식으로 바꾼다.
   우리증거: [호증번호]_원래파일명.확장자  (예: 노제24호증_인사기록카드.pdf)
   상대증거: [호증번호]_원래파일명.확장자  (예: 사제1호증_징계처분서.pdf)

   호증번호는 3·4단계에서 판단한 결과를 그대로 쓰고, 적용은 스크립트로 한다.
   `{사건}/증거관리/리네임계획.json` 에 아래 형식으로 적은 뒤 실행한다.

   ```json
   {"items": [{"path": "4_서면작성/사건/{사건}/라운드N/우리증거/문서.pdf", "호증": "노제24호증"},
              {"path": "...", "호증": "갑제9호증", "name": "갑제9호증_동아일보 기사.pdf"}]}
   ```

   ```powershell
   python 4_서면작성/scripts/evidence_rename.py "4_서면작성/사건/{사건}/증거관리/리네임계획.json"
   python 4_서면작성/scripts/evidence_rename.py "4_서면작성/사건/{사건}/증거관리/리네임계획.json" --apply
   ```

   `--apply` 없이 먼저 미리보기를 보고, `blocked` 가 비어 있는지 확인한 뒤 적용한다.
   스크립트는 이름을 임의로 줄이지 않으므로 계획에 적은 이름이 곧 파일명이 되고,
   호증목록에는 그 이름을 그대로 옮겨 적는다.

   **증거 파일명은 짧게 짓는다.** 법원 전자소송에서 내려받은 파일명은 같은 제목이 두 번
   들어가고 뒤에 제출자와 대리인 이름이 붙어 200자를 넘기기도 한다. 이런 파일은 `name` 에
   `[호증번호]_[무슨 문서인지]` 형태의 짧은 이름을 지정해서 함께 정리한다. 사건번호나 날짜가
   식별에 필요하면 남기고, 중복된 제목과 대리인 이름은 지운다.

6. 작업 완료 후 이번 라운드에서 새로 추가된 증거 목록을
   한눈에 볼 수 있게 요약해서 보고해줘.
   우리 증거 N건, 상대 증거 N건, 호증번호 범위 포함.
