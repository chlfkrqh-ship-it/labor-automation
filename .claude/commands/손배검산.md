`$ARGUMENTS` 로 지정한 파일(대법원 프로그램 엑셀표저장 결과, 상대방 별지 산정표,
직접 만든 산정표 등)을 읽어 계산이 맞는지 검산한다.

작업 전에 `6_손해배상계산/CLAUDE.md` 를 읽는다.

## 계산 폴더

검산에 쓰는 검산용 입력(`검산_사건.yaml`)·즉석 스크립트·검산표는 대상 파일이 속한 사건의 **계산 폴더**에 둔다.
저장소 루트나 `6_손해배상계산/` 바로 아래에는 만들지 않는다. 그 자리는 시스템 파일과 함께 git 으로
올라가는 자리여서, 별지에서 옮긴 성명·생년월일·임금과 이름에 성명이 든 계산표가 GitHub 에 올라간다.

| 대상 파일 위치 | 계산 폴더 |
|---|---|
| `4_서면작성/사건/{사건명}/라운드N/…` | `4_서면작성/사건/{사건명}/라운드N/작업/계산/` |
| `1_검토의견/사건/{폴더}/…` | `1_검토의견/사건/{폴더}/계산/` |
| `6_손해배상계산/사건/{사건명}/…` | 같은 폴더 |
| 그 밖(채팅 첨부, 저장소 밖 경로 등) | `6_손해배상계산/사건/{사건명}/` |

`.claude/commands/손배계산.md` 0절과 같은 규칙이다. 대상 파일은 복사하지 않는다. 계산 폴더가 없으면 만든다.
명령은 `6_손해배상계산/` 안에서 돌리므로 다른 폴더는 `../4_서면작성/사건/{사건명}/라운드N/작업/계산/` 처럼 `../` 를 붙인다.

**검산용 파일은 `/손배계산` 의 파일과 이름을 달리한다.** 한 서면 라운드에서는 `/손배계산` 과 `/손배검산` 이 같은 계산 폴더(`라운드N/작업/계산/`)를 쓴다.
검산용 입력은 `검산_사건.yaml` 로 만들고 `/손배계산` 의 `사건.yaml` 을 고치거나 덮어쓰지 않는다. 엔진은 늘 `-o` 로 검산표 이름을 주어 돌린다.
`cli.py` 는 `-o` 가 없으면 노동 금액은 입력 파일 옆의 `{사건번호}({성명})_노동금액계산표.xlsx` 에, 신체손해는 `6_손해배상계산/out/{사건번호}({성명}).xlsx` 에 쓴다.
이 이름은 입력 파일 이름이 아니라 사건번호·성명으로 정해지므로, 입력 이름만 달리하고 `-o` 를 빼면 노동 금액은 `/손배계산` 이 만든 계산표(사건번호·성명이 같은 것)를 덮어쓰고 신체손해는 계산표가 계산 폴더 밖에 생긴다.

## 순서

1. 파일을 읽어 기초사항과 계산 구조를 파악한다. 어떤 방식으로 계산했는지 먼저 적는다.
2. 같은 입력으로 엔진을 돌려 대조한다. `6_손해배상계산/` 에서 파이썬을 직접 짜서
   `engine.hoffman`, `engine.schedule`, `engine.settlement` 을 호출한다.
   - 즉석 스크립트는 파일로 만들지 않고 표준입력으로 넘긴다(`python -B - <<'EOF'` … `EOF`).
     남겨 둘 스크립트는 계산 폴더에 `검산_{항목}.py` 로 두고, 첫 줄에 `import sys; sys.path.insert(0, '.')` 를 넣어
     `6_손해배상계산/` 에서 `python -B <계산 폴더>/검산_{항목}.py` 로 돌린다.
   - 사건 전체를 다시 계산할 때에는 계산 폴더에 `검산_사건.yaml` 을 만들고
     `python cli.py <계산 폴더>/검산_사건.yaml -o <계산 폴더>/{사건명}_검산표.xlsx` 로 돌린다.
3. 항목별로 일치·불일치를 표로 낸다. 불일치는 **원인**까지 짚는다.
4. 표를 넘기기 전에 자체 검토를 통과시킨다(`공통/자체검토.md`). 검증자에게는 대상 파일(복사하지 않고 경로로), 검산에 쓴 `검산_사건.yaml`·`검산_{항목}.py`, 검산표, 넘길 두 표(이상 없는 항목, 불일치 항목)를 준다. 옵션을 바꾸어 한 번 더 돌렸으면 그 입력 `검산_사건_대안.yaml` 과 대안계산표도 함께 준다(아래 '노동 금액 검산'). 불일치 표에 들어가는 검산값을 낸 스크립트는 즉석 실행으로 끝내지 않고 `검산_{항목}.py` 로 남긴다. 검토 기록은 계산 폴더의 `자체검토/` 에 두고, 검증자가 엔진을 다시 돌릴 때에도 `-o <계산 폴더>/자체검토/재현_검산.xlsx`(대안 입력은 `재현_대안.xlsx`)처럼 그 폴더에 써서 검산표를 덮어쓰지 않는다. `/손배계산` 5절의 검증자가 같은 폴더에 쓰는 `재현.xlsx` 와 이름을 달리하여, 한 계산 폴더에서 두 명령을 잇달아 하여도 앞의 재현 출력을 덮어쓰지 않게 한다.
   - 대상값이 대상 파일의 그 칸과 같은지, 엔진에 넣은 입력이 대상 파일의 기초사항과 같은지 본다.
   - 검산값은 검증자가 엔진을 다시 돌린 출력과 대조한다. 검증자도 금액을 직접 계산하지 않는다.
   - '원인'은 그 옵션·구방식으로 다시 돌렸을 때 대상값이 나오는지로 확인한다. 나오지 않은 원인은 '추정'으로 적는다.
   - '이상 없는 항목'에는 실제로 대조한 항목만 둔다.

## 자주 나오는 불일치 원인

| 증상 | 원인 |
|---|---|
| 호프만 계수가 다름 | `240 − H(제외)` 구방식. 2022다211393에 따르면 `min(H(총)−H(제외), 240)` |
| 노임이 한 단계 다름 | 반기 경계를 달력 반기로 봄. 실제는 9.1.~4.30. / 5.1.~8.31. |
| 마지막 자리가 1~2원 다름 | 끝수처리. 누적합은 절사, 적용호프만 차이는 반올림, 금액은 원 미만 절사 |
| 연령이 하루 다름 | 연령은 초일산입 없음(`age_at`), 기간은 초일산입 있음(`diff_ymd`) |
| 치료비 수치합계가 다름 | 상한이 20이 아니라 `240 ÷ 수명(월)` |
| 순번 경계가 다름 | 입원치료 종료일 다음날에서도 끊긴다. 미래 구간은 마지막 단가로 묶는다 |
| 중복장해율·기왕증 기여도가 0.01%p 다름 | 2026. 9. 23. 전에 이 시스템이 만든 계산표는 부동소수점 오차로 0.01%p 낮을 수 있다(예: 10% → 9.99%). 지금 엔진은 10진수로 계산한다 |

## 노동 금액 검산

상대방 별지나 판결 계산표가 노동 금액(통상시급, 시간외수당·퇴직금·연차수당 차액, 해고기간 임금, 지연손해금)이면
같은 입력으로 계산 폴더에 `kind: labor` 인 `검산_사건.yaml` 을 만들어
`python cli.py <계산 폴더>/검산_사건.yaml -o <계산 폴더>/{사건명}_검산표.xlsx` 로 돌리고 대조한다
(`.claude/commands/손배계산.md` 3절). `-o` 를 빼면 계산표가 입력 파일 옆에 `{사건번호}({성명})_노동금액계산표.xlsx` 로 생겨,
같은 계산 폴더에서 `/손배계산` 이 만든 계산표(사건번호·성명이 같은 것)를 덮어쓴다(위 '계산 폴더').
상대 계산 방식에 맞는 옵션이 있으면 그 옵션으로 한 번 더 돌려, 차이가 옵션(해석)인지 산식 오류인지 가른다.
다시 돌릴 때에는 `검산_사건.yaml` 을 고쳐 쓰지 않고 옵션만 바꾼 `검산_사건_대안.yaml` 을 따로 만들어
`python cli.py <계산 폴더>/검산_사건_대안.yaml -o <계산 폴더>/{사건명}_대안계산표.xlsx` 처럼 입력과 출력의 이름을 모두 달리 주어 돌린다.
`검산_사건.yaml` 을 고쳐 돌리면 순서 4의 검증자에게 주는 입력이 검산표가 아니라 대안계산표의 입력이 되고, `-o` 에 같은 이름을 주면 앞 검산표를 덮어쓴다.
두 입력과 두 계산표를 모두 순서 4의 검증자에게 준다.

| 증상 | 원인 |
|---|---|
| 통상시급이 조금 다름 | 월 기준시간 208.57/209/226/243, 시급을 원 단위로 먼저 끊음(`ow_month_hours_rounding`, `ow_hourly_rounding`) |
| 2024. 12. 19. 전후 수당이 같은 시급 | 새 통상임금 법리(고정성 폐기) 적용 시점 구분 누락. 병행사건은 소급 |
| 연장시간이 많음 | 1일 8시간 초과분과 1주 40시간 초과분 중복 산입 |
| 휴일근로 가산이 적음 | 2018. 3. 20. 이후 휴일 8시간 초과분 100% 누락 / 그 전 기간은 휴일근로를 주 40시간에 넣음 |
| 4명 이하 사업장에 가산 | 상시 4명 이하 기간은 연장·휴일 가산 미적용 |
| 기지급액 공제 방식 | 월별 비교와 전체 기간 합산 비교, 초과 지급분 충당 여부(`ot_compare_unit`) — 판례 불명확 |
| 평균임금 산정기간 하루 차이 | 산정사유 발생일 초일 산입. 퇴직금은 마지막 근무일까지가 산정기간 |
| 평균임금이 높음/낮음 | 상여·연차수당 3/12 산입, 퇴직으로 비로소 생긴 연차수당 산입, 통상임금 하한 비교 방식 |
| 퇴직금 수십~수천 원 차이 | 지급률(재직일수/365)을 소수 셋째 자리에서 버림, 구간별 버림 |
| 연차수당 10원 단위 차이 | 1일분을 먼저 끊고 곱함 / 10원 미만 버림 |
| 중간수입 공제가 큼 | '중간수입 − 휴업수당'을 공제(위법 산식). 옳은 산식은 월별 min(중간수입, 임금 − 휴업수당) |
| 중간수입 공제가 없음 | 중간수입이 휴업수당보다 적다고 공제 전부 배제(위법) / 다른 달 수입을 끌어옴(기간 대응 위반) |
| 지연손해금 20% 기산 하루 차이 | 퇴직 청산 금품은 마지막 근무일 + 15일부터. 14일째가 일요일이어도 연장하지 않음 |
| 지연손해금 수 원 차이 | 1년 넘는 기간의 잔여일 분모(365/366), 구간별 버림 |
| 해고기간 임금에 20% | 구법 도래분·복직이면 20% 없음(2014다28305). 개정법 도래분은 하급심이 갈림 |

## 출력

- 이상 없는 항목 (표)
- 불일치 항목 (표: 대상값 / 검산값 / 원인 / 영향액)
- 판례 쟁점이 걸린 항목은 근거 판결을 함께 적는다
- 자체 검토 결과(`공통/자체검토.md` 10절의 항목). 원문과 대조한 인용 수는 대상 파일·엔진 출력과 대조한 항목 수로 적고, 근거 판결은 판결 원문과 대조하지 않았다고 적는다. 확인하지 못한 것에는 대상값을 재현하지 못한 원인과 대조하지 않은 항목을 적는다

**금액을 직접 계산하지 않는다.** 검산값은 반드시 엔진 출력을 쓴다.
