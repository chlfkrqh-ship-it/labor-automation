# LBOX 하이라이트

실제 브라우저 작업 전에 `공통/브라우저.md`를 읽는다. **인앱 브라우저의 LBOX 로그인 상태를 먼저 확인하고, 로그인되어 있지 않으면 외부 엣지 브라우저로 한다.** 아래 도구명·DOM·GET 예시는 해당 환경에서 허용되는 동등한 조작으로 적용한다.

사용자가 나중에 근거를 직접 다시 확인할 수 있게 하기 위한 것이다. **대상은 판례·결정례·유권해석이다.** 법령에는 하지 않는다.

| 자료 | 원문 주소 | 하이라이트 조회 |
|---|---|---|
| 판례 | `https://lbox.kr/case/{법원명}/{사건번호}` | `GET /gw/research/api/v3/precedents/{법원명}-{사건번호}/highlights` |
| 결정례 | `https://lbox.kr/decision/{documentId}` | `GET /gw/research/api/v3/decisions/{documentId}/highlights` |
| 유권해석 | `https://lbox.kr/interpretation/{documentId}` | `GET /gw/research/api/v3/interpretations/{documentId}/highlights` |

`documentId`는 `lbox-검색` 스킬 `lboxRow`의 `id`이고 주소에는 `encodeURIComponent`로 넣는다(`lboxRow`의 `url`을 그대로 써도 된다). 결정례·유권해석도 판례와 같은 팔레트가 뜨고 저장·삭제되는 것을 2026. 9. 17. 인앱 브라우저에서 확인했다(노동위원회 판정의 판정요지, 법제처 법령해석의 회답).

**화면에 글자로 나오는 부분만 칠할 수 있다.** 재결서 등 전문이 PDF 뷰어로 나오는 결정례는 전문 글자를 선택해도 팔레트가 뜨지 않는다(2026. 9. 17. 고용보험심사위원회 재결서, 스크립트 선택과 실제 드래그 모두). 인용한 부분이 이런 곳에 있거나 저장이 확인되지 않으면 억지로 칠하지 않고, 답변 말미에 그 자료의 원문 링크와 인용 위치(쪽·항목·첫 구절)를 적어 사용자가 직접 확인할 수 있게 한다.

## 색 체계

색은 작업 유형으로 구분한다. 팔레트 순서는 왼쪽부터이다.

| 색 | 언제 | 팔레트 | RGB |
|---|---|---|---|
| **노랑** | 검토의견(이메일·서면)에 실제로 인용한 판례 | 1번 | `rgb(251,191,36)` |
| **연두** | 서면작성(`/서면`)으로 찾아 서면 초안에 인용할 판례 | 2번 | `rgb(163,230,53)` |
| **파랑** | 질의 관련 판례를 조사하여 나열한 것 | 3번 | `rgb(56,189,248)` |
| **보라** | 사용자가 쓴 서면의 주장을 보강하는 판례 | 4번 | `rgb(167,139,250)` |
| (분홍) | 미사용 | 5번 | `rgb(244,114,182)` |
| (회색) | 미사용 | 6번 | `rgb(161,161,170)` |

**칠하려는 부분에 이미 하이라이트가 있으면 색에 관계없이 기존 것을 지우고 이번 작업 색으로 새로 칠한다.** 하이라이트는 사용자가 이번 작업이 실제로 수행되었는지 직접 검증하는 절차이므로, 남아 있던 하이라이트를 그대로 두면 이번에 칠한 것인지 예전 것인지 구별되지 않는다. 덧칠하거나 건너뛰지 않는다.

작업 전에 맨 위 표의 자료별 조회 경로로 기존 하이라이트를 먼저 조회하고, 지운 색이 무엇이었는지 답변에 남긴다.

## 하이라이트 범위

근거가 되는 **문장 전체**(주어부터 '~한다.'까지)로 잡는다. 판시사항(제목 형식)이 아니라 **판결요지 또는 이유 중 해당 판단 부분**을 잡는다.

**칠할 문장을 낱말로 자동 검색해 고를 때에는 칠하기 전에 그 문장이 무엇인지 눈으로 확인한다.** 낱말만 보고 첫 번째로 걸리는 문단을 잡으면 판단이 아닌 곳이 잡힌다. 2026. 9. 20. 같은 낱말로 자동 선택한 결과 서울행정법원 2022구합82813에서는 **근로복지공단의 처분 이유**(처분의 경위)가, 대법원 2015두48136에서는 **판시사항**이 잡혔다. 그대로 칠했으면 당사자·처분청의 주장을 법원의 판단처럼 표시해 두는 셈이 된다(루트 공통 규칙 '판결·결정문 속 당사자 주장을 법원 판단처럼 인용하지 않는다'). 선택된 문장을 되돌려 받아 '2. 판단', '판결요지', '가. …에 대한 판단' 아래의 문장인지 확인한 뒤 칠한다. 결정례는 판정사항이 아니라 **판정요지 또는 전문 중 해당 판단 부분**을, 유권해석은 질의(갑설·을설 포함)가 아니라 **회시·회답 중 해당 부분**을 잡는다.

## 실행 방법

1. 판례 상세 URL은 `https://lbox.kr/case/{법원명}/{사건번호}` 형식이고 법원명은 공백 없이 붙여 쓴다(예: `수원지방법원여주지원`). 결정례·유권해석은 맨 위 표의 주소로 연다. **원문을 열 때마다 먼저 `lbox-검색` 3항 '원문 열기' 블록을 그 주소로 실행하고, 오류 없이 끝나면 그 주소로 옮긴다.** 원문을 여는 것도 본문 수신과 같은 사용량 기록·한도·간격에 넣기 위한 것이다(2026. 9. 19. 사용자 결정). 블록이 한도 초과나 멈춤 표시로 오류를 내면 열지 않고 사용자에게 알린다. 옮긴 주소에 `/recaptcha`가 있으면 `lbox-검색` 3항 '이용 확인 화면이 뜨면'대로 모든 LBOX 작업을 멈춘다.
2. 선택 전에 해당 문단을 `scrollIntoView`로 화면 가운데에 올려 둔다.
3. 본문 텍스트 노드에서 `Range`를 만들어 선택한 뒤 `document`에 `mouseup` 이벤트를 디스패치하면 색상 팔레트가 있는 플로팅 툴바가 뜬다. **툴바는 1초쯤 뒤에 뜨므로 디스패치 직후에 버튼을 찾으면 없다.** 한 번 더 조회하거나 스크린샷을 찍어 확인한 뒤 좌표를 읽는다.
   - **판결 본문은 `innerText`로 일부만 나온다.** 화면 밖 문단이 빠지기 때문이다(2026. 9. 20. 엣지에서 본문 11만 자 가운데 `innerText`는 2천 자). 문단은 `document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT)`로 훑어 인용할 문장이 든 텍스트 노드를 찾는다.
4. **색상 버튼은 스크립트 클릭으로는 적용되지 않는다.** 실제 마우스 클릭(computer 도구의 `left_click`)으로 눌러야 한다.
5. 인앱 브라우저로 할 때에는 작업 전에 **뷰포트를 1280×900 정도로 키운다.** 인앱 브라우저의 기본 좌표 프레임은 800×450이어서 팔레트가 화면 밖에 잡힌다. 턴이 끝나면 앱이 되돌리므로 다음 턴에 다시 설정한다.
6. 브라우저 패널이 그려지지 않은 상태에서는 툴바 좌표를 조회할 수 없다. **저배율 스크린샷을 한 번 찍어 렌더를 강제한 뒤** 좌표를 조회한다. Claude 창이 다른 창에 가려 있으면 스크린샷이 시간 초과되므로 한 번 다시 찍는다.
7. **색상 버튼은 `aria-label`로 찾되, 찾히지 않으면 스크린샷 좌표로 한다.** `[aria-label="하이라이트 green"]` 형태이고 2026. 9. 16. 인앱 브라우저에서 여섯 개가 모두 확인되었다. **다만 2026. 9. 20. 엣지에서는 팔레트가 화면에 떠 있는데도 `[aria-label^="하이라이트 "]`가 계속 0개를 돌려주었다.** `button`·`[role="button"]`을 훑어도 나오지 않았다. 그때는 배율 1 스크린샷을 찍어 색 원의 좌표를 직접 읽는다. 원은 왼쪽부터 노랑·연두·파랑·보라·분홍·회색 순서로 26~27px 간격이고, 한 줄로 붙어 있다. **몇 번째 원인지 세어 클릭하므로 한 칸만 어긋나도 다른 색이 저장된다.** 2026. 9. 20. 대법원 2012다77006을 파랑 대신 노랑으로 칠한 일이 있었다.

   | 작업 색 | `aria-label` |
   |---|---|
   | 노랑 | `하이라이트 yellow` |
   | 연두 | `하이라이트 green` |
   | 파랑 | `하이라이트 sky` |
   | 보라 | `하이라이트 violet` |
   | (분홍·회색, 미사용) | `하이라이트 red` · `하이라이트 zinc` |

8. **팔레트는 선택한 문단보다 아래에 뜨는 경우가 있어 화면 밖에 잡힐 수 있다.** `getBoundingClientRect()`의 `y`가 뷰포트 높이를 넘으면 먼저 스크롤하여 화면 안으로 들인 뒤 좌표를 다시 조회하고 클릭한다.
9. **저장 여부는 건수가 아니라 색까지 확인한다.** 맨 위 표의 자료별 조회 경로로 조회하고 응답의 `"color"` 값이 이번 작업 색인지 본다. 건수만 보면 색이 틀린 것을 잡지 못한다(2026. 9. 20. 노랑으로 저장된 것을 건수로는 성공으로 오인했다).
10. **조회는 색 버튼을 누른 뒤 5~10초 지나서 한다.** 저장 요청이 늦게 반영되어 3초·6초에도 0건으로 나오다가 그 뒤에 1건이 되는 일이 2026. 9. 20. 세 번 있었다(종전 기록은 2~3초). 0건이 나왔다고 곧바로 다시 칠하면 같은 문장에 두 건이 겹친다. 화면 오른쪽 패널의 하이라이트 탭에 뜨는 숫자가 API보다 먼저 올라가므로 함께 본다.

### 기존 하이라이트 지우기·색 바꾸기

**칠하려는 범위와 같은 문장에 하이라이트가 이미 있으면 지우고 새로 칠하는 대신 색만 바꾸는 편이 간단하다.** 그 span을 클릭해 뜬 팝오버의 팔레트에서 이번 작업 색을 누르면 같은 하이라이트의 색이 바뀐다(2026. 9. 20. 대법원 2012다77006에서 노랑 → 파랑으로 바꾸고 `"color":"sky"`로 확인). 하이라이트가 한 건 그대로 유지되므로 겹쳐 쌓이지 않는다. 범위가 다른 하이라이트를 치울 때에는 아래대로 지운다.

1. `DELETE` API 직접 호출은 차단되므로 화면에서 지운다.
2. 지울 하이라이트는 `span[class*="bg-highlight-{색}-"]`로 찾는다. 같은 문장에 여러 색이 겹쳐 있으면 span도 겹쳐 있어 클릭이 엉뚱한 것을 잡을 수 있으므로, span 왼쪽 끝에서 40~60px 안쪽을 노린다.
   - **판결 본문에는 다른 판례·조문 링크가 섞여 있으므로 링크를 피해 누른다.** 2026. 9. 20. 하이라이트 첫 줄을 눌렀다가 그 안의 '대법원 2008. 10. 23. 선고 2007다7973 판결' 링크가 눌려 다른 사건으로 넘어갔다(그 페이지 열기도 사용량에 든다). 여러 줄에 걸친 하이라이트는 링크가 없는 **마지막 줄**을 고르고, `getClientRects()`로 줄마다 좌표를 받아 고른다.
3. 그 span을 **실제 마우스 클릭**하면 색상 팔레트 + `설명 남기기` + `삭제`가 있는 팝오버가 뜬다. 팔레트에서 체크 표시가 붙은 색이 지금 잡힌 하이라이트이므로, 지우려는 색이 맞는지 확인하고 `삭제`를 누른다.
4. **팝오버는 다시 클릭하면 닫히므로 클릭을 반복하지 않는다.** 좌표를 확인하려면 클릭과 같은 배치 안에서 `zoom`으로 팝오버 영역을 찍고, 다음 배치에서 곧바로 `삭제`를 누른다. 같은 화면에서 방금 칠한 하이라이트는 첫 클릭에 팝오버가 뜨지 않을 수 있는데, 이때에는 찍은 화면에 팝오버가 없는 것을 확인한 경우에만 한 번 더 누른다(2026. 9. 17. 결정례·유권해석 시험에서 두 번 모두 두 번째 클릭에 떴다).
5. 색이 여러 개면 한 번에 하나씩 지워지므로, `GET .../highlights`가 빌 때까지 2~4를 반복한다.
6. 겹친 하이라이트에서 지우려는 색이 잡히지 않으면 억지로 클릭하지 말고, 어느 색이 남았는지 사용자에게 알리고 화면에서 직접 지우도록 한다.

### 좌표가 어긋날 때

**좌표는 스크린샷 결과에 적힌 좌표 프레임을 기준으로 한다.** 축소 배율로 찍어도 좌표는 언제나 그 프레임 기준이지 이미지 픽셀 기준이 아니다. 한 작업 안에서 프레임이 다른 스크린샷을 섞으면 클릭이 빗나가므로 배율을 하나로 통일한다.

DOM에서 읽은 좌표는 `rect.x * 프레임가로 / window.innerWidth`, `rect.y * 프레임세로 / window.innerHeight` 로 환산한다. 페이지가 다시 그려졌거나 스크롤되었으면 환산 전에 스크린샷을 새로 찍는다.

**ref 기반 클릭은 이 화면에서 좌표가 틀어지므로 쓰지 않는다.**

## 마무리

판례·결정례·유권해석별로 몇 건에 하이라이트를 남겼는지 답변 말미에 한 줄로 밝힌다. 칠하지 못한 자료가 있으면 그 아래에 원문 링크, 인용 위치, 칠하지 못한 이유(PDF 전문, 저장 미확인 등)를 적는다.
