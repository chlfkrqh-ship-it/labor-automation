# 사업자·사업장 확인

공공데이터포털(data.go.kr)의 두 API를 `공통/scripts/datago.py`로 부른다. **법제처 API와는 다른 포털이므로 인증키가 따로 있다.** 브라우저와 LBOX 한도와는 무관하다.

| 무엇 | 어디서 | 무엇을 알 수 있나 |
|---|---|---|
| 사업자등록 상태 | 국세청 | 계속·휴업·**폐업**과 폐업일자, 과세유형 |
| 국민연금 가입 사업장 | 국민연금공단 | 사업장의 **국민연금 가입자 수**, 당월 고지금액, 업종, 등록·탈퇴일 |

## 1. 처음 한 번 — 인증키

**data.go.kr에는 인증키만 따로 받는 페이지가 없다.** API를 하나 활용신청하면 그때 계정에 인증키가 생긴다. **인증키는 계정에 하나지만 API마다 따로 활용신청해야 한다.** 신청하지 않은 API는 같은 키로도 `등록되지 않은 서비스키`로 막힌다(2026. 9. 20. 실측).

1. [data.go.kr](https://www.data.go.kr) 회원가입·로그인
2. 쓸 API를 각각 **활용신청**한다(둘 다 자동승인이라 곧바로 승인된다)
   - [국세청_사업자등록정보 진위확인 및 상태조회 서비스](https://www.data.go.kr/data/15081808/openapi.do)
   - [국민연금공단_국민연금 가입 사업장 내역](https://www.data.go.kr/data/3046071/openapi.do)
3. 우측 상단 **마이페이지 → 오픈API → 인증키 발급현황** 에서 일반 인증키를 본다. 신청한 서비스별로는 **마이페이지 → 오픈API → 개발계정 → (서비스 선택) → 서비스정보**에도 같은 키가 있다
4. **Encoding·Decoding 두 가지가 보이는데 어느 쪽을 넣어도 된다.** `datago.py`가 한 번 풀고 다시 넣는다

신청과 키 확인은 사용자가 직접 한다. 인증키를 채팅에 받거나 대신 입력하지 않는다.

```powershell
python 공통/scripts/datago.py set-key 인증키
python 공통/scripts/datago.py check
```

인증키는 `%LOCALAPPDATA%\노동사건자동화\datago.json`에 저장되고 OneDrive에는 올라가지 않는다. **회사 PC와 집 PC에서 각각 한 번씩 저장한다.** `check`가 `인증키나 신청 상태를 확인하십시오`를 내면 활용신청이 승인되지 않았거나 키가 틀린 것이다.

## 2. 사업자등록 상태 — 무엇이 오는가

```powershell
python 공통/scripts/datago.py 사업자 1234567890 123-45-67890
python 공통/scripts/datago.py 사업자 1234567890 --out "{사건}/라운드N/작업/사업자상태.json"
```

| 칸 | 값 |
|---|---|
| 상태 / 상태코드 | `계속사업자` 01 · `휴업자` 02 · `폐업자` 03 |
| 폐업일자 | 폐업자일 때 `2024-01-31` 꼴. 아니면 빈 값 |
| 과세유형 | 부가가치세 일반과세자·간이과세자·면세사업자 등 |
| 과세유형전환일자 / 세금계산서적용일자 | 있을 때만 |

- 사업자등록번호는 하이픈이 있어도 되고, **한 번에 100개까지** 넘긴다(국세청 제한: 1회 100건, 하루 100만 건).
- 국세청에 없는 번호는 `조회안됨`에 모으고 표에도 `국세청에 등록되지 않은 번호`로 남긴다. **빠뜨리지 않는다.**

**`등록되지 않은 번호`와 `형식 오류`를 반드시 구별한다.** 사업자등록번호 끝자리는 앞 아홉 자리로 정해지는 검증번호인데, **국세청은 검증번호가 틀린 번호에도 똑같이 '등록되지 않은 사업자등록번호입니다'로 답한다.** 그대로 옮기면 오타를 "상대방이 국세청에 등록되어 있지 않다"로 잘못 쓰게 된다. `datago.py`가 보내기 전에 검증번호를 계산해 틀리면 `형식오류`로 가르고 호출하지 않는다.

2026. 9. 20. 이 구별이 실제로 문제가 되었다. `106-87-04597`을 조회하니 '등록되지 않은 번호'로 나왔는데, 검증번호가 0이어야 할 자리가 7이어서 **실재할 수 없는 번호**였다. 끝자리를 맞춘 `106-87-04590`은 실재하지만 2015. 3. 31. 폐업한 **다른 사업자**였다. **검증번호를 맞춰 얻은 번호는 원래 찾던 사업자가 아니다.** 끝자리만 바꿔 맞는 번호를 찾아다니지 않고, 사업자등록증·세금계산서·홈택스에서 정확한 번호를 받는다.

## 3. 국민연금 가입 사업장

```powershell
python 공통/scripts/datago.py 사업장 --이름 "법무법인 평안" --상세 --최신만
python 공통/scripts/datago.py 사업장 --이름 "법무법인 평안" --상세            # 월별 추이까지
python 공통/scripts/datago.py 사업장 --사업자번호 1234567890 --상세 --최신만
python 공통/scripts/datago.py 사업장 --이름 "평안" --상세 --limit 60 --out "{사건}/라운드N/작업/사업장.json"
```

**한 사업장이 자료기준월마다 한 줄씩 온다(최근 12개월).** 검색 결과의 `전체`·`받은건수`는 사업장 수가 아니라 **줄 수**이다. 사업장이 몇 곳인지는 `사업장수`와 `요약`을 본다. `--limit` 기본값 24는 두 사업장의 1년치에 해당한다.

- **지금 규모만 알면 될 때는 `--최신만`을 붙인다.** 사업장마다 최근 달 한 줄만 남기고, 상세 호출도 그만큼만 나간다(법무법인 평안 조회에서 13회 → 2회).
- **해고일 무렵의 규모가 쟁점이면 `--최신만`을 빼고 월별 줄을 그대로 본다.** 상시 근로자 수 다툼에서는 이 추이가 핵심 자료가 된다.

- `--이름`은 상호의 **부분 일치**이다. **띄어쓰기를 등록된 상호 그대로 맞춰야 한다.** `법무법인 정격` 1건, `정격` 1건인데 `법무법인태평양`은 0건이다(2026. 9. 20. 실측).
- `--사업자번호`는 **앞 6자리만** 쓴다(국민연금이 앞 6자리만 공개하고, 응답도 `871870****` 꼴로 뒤를 가린다). **앞 6자리는 세무서·유형 코드라 잘 좁혀지지 않는다**(`116810` → 1,175건). 이름으로 찾고 주소·업종으로 특정하는 편이 낫다.
- `--상세`를 붙여야 **가입자수·당월고지금액·업종·등록일·탈퇴일**이 온다. 건마다 호출이 한 번 더 나가므로 대상을 좁힌 뒤에 붙인다.
- 목록만 받으면 사업장명·사업자번호 앞 6자리·주소·법인/개인·등록/탈퇴·자료기준월이 온다.
- **업종이 유용하다.** 법률사무소는 `변호사업`(코드 741101)으로 나온다. 같은 이름이 여럿일 때 이것으로 가른다.

2026. 9. 20. 우리 법인을 조회한 예이다. 12개월치가 한 줄씩 왔다.

```
기준월   사업장명      주소                     가입자수   당월고지금액   등록일        업종
202607  법무법인 평안  서울특별시 서초구 서초대로50길    54   24,785,220  2014-11-01  변호사업
202606  법무법인 평안  서울특별시 서초구 서초대로50길    54   23,802,620
202605  법무법인 평안  서울특별시 서초구 서초대로50길    56   24,682,020
 …
202508  법무법인 평안  서울특별시 서초구 서초대로50길    48   20,052,140
```

기술적인 사항(다음에 고칠 때를 위해) — V2는 요청 파라미터가 **camelCase**(`wkplNm`·`bzowrRgstNo`)이고, snake_case로 보내면 조건이 무시되어 0건이 온다. 응답은 `resultType=json`을 줘도 **XML로만** 온다. 탈퇴하지 않은 사업장의 탈퇴일은 `00010101`로 온다. `datago.py`가 이를 모두 처리한다.

## 4. 국민연금 자료의 한계 — 이것을 빼고 쓰지 않는다

**가입자 수는 근로기준법상 상시 근로자 수가 아니다.** 둘은 여러 갈래로 어긋난다.

- 국민연금 사업장가입자에서 빠지는 사람이 있다(18세 미만으로 가입하지 않은 사람, 60세 이상, 월 60시간 미만 단시간, 일용, 이미 다른 사업장에서 가입한 사람 등). 이때는 **실제보다 적게** 나온다.
- 반대로 대표이사·임원처럼 근로기준법상 근로자가 아닌 사람이 가입자에 들어 있을 수 있다. 이때는 **실제보다 많게** 나온다.
- 상시 근로자 수는 근로기준법 시행령 제7조의2대로 **법 적용 사유 발생일 전 1개월 동안의 연인원을 가동일수로 나누어** 센다. 특정 시점의 가입자 수와는 셈법 자체가 다르다.

**수록 범위도 좁다.** 가입자 **3인 이상 법인사업장, 10인 이상 개인사업장**만 실린다(2025. 7. 이후 기준). 개인 법률사무소처럼 5인 경계에 걸린 개인사업장은 **아예 목록에 없다.** 따라서 **목록에 없다고 5인 미만이라고 쓰지 않는다.** 그 경우 알 수 있는 것은 "10인 미만"뿐이다.

- 자료는 자격 신고 기한의 **다음 달 15일까지 신고분**이 반영된다. 최근 입·퇴사는 시차가 있다.
- 사업자등록번호가 앞 6자리만 공개되므로 같은 상호·비슷한 번호를 가려내기 어렵다. **주소·업종·등록일을 함께 보고 특정한다.**
- 쓸 수 있는 자리는 ① 사업장이 국민연금에 가입되어 있는지, ② 규모가 대략 어느 정도인지, ③ 언제 등록·탈퇴했는지까지이다. 상시 5인 이상 여부는 **4대보험 자격취득 자료·급여대장·근로계약서**로 따로 증명한다.

## 5. 국세청 자료의 한계

- **국세청 등록 정보는 30분 주기로 갱신되고, 새로 낸 사업자는 1~2일 뒤에 나타난다.** 최근 폐업·개업은 시차가 있을 수 있다.
- **상시 근로자 수는 알 수 없다.** 이 API는 사업자 상태와 과세유형만 준다.
- **폐업으로 나왔다고 사용자가 사라진 것이 아니다.** 법인 폐업과 법인격 소멸은 다르고, 개인사업자는 폐업해도 채무가 남는다.
- **위장폐업은 이 자료만으로 증명되지 않는다.** 같은 장소·같은 근로자·같은 영업이 이어졌는지를 따로 본다.

## 6. 언제 쓰는가

- **해고 뒤 폐업·위장폐업 다툼.** 폐업일자가 해고일 뒤인지 앞인지, 같은 대표가 다른 번호로 계속사업자인지 본다. 국민연금 사업장의 탈퇴일과 맞춰 보면 언제 사람을 내보냈는지 가늠할 수 있다.
- **구제이익.** 사업장이 폐업하면 원직복직이 불가능해져 구제신청의 이익이 문제된다(대법원 2020두54852 등). 폐업 여부를 먼저 확인하고 서면에 쓴다.
- **체당금·임금채권보장.** 도산등사실인정의 전제 사실이다.
- **당사자 표시와 송달.** 상대방이 실재하는지, 휴업 중인지 확인한다.
- **상시 근로자 수 다툼의 출발점.** 국민연금 가입자 수로 규모를 가늠하되, 4항의 한계를 빼지 않고 함께 적는다. 이 수치만으로 5인 이상·미만을 단정하지 않는다.

## 7. 서면·검토의견에 옮길 때

**조회한 날짜와 조회 대상을 함께 적는다.** 자료마다 기준이 다르므로 무엇을 본 것인지 드러나야 한다.

- `국세청 사업자등록 상태조회(2026. 9. 20. 기준) 결과 폐업자(폐업일자 2024. 1. 31.)로 확인된다`
- `국민연금 가입 사업장 내역(2026. 9. 20. 조회, 자료기준 2026. 8.)에 국민연금 가입자 7명으로 기재되어 있다. 다만 국민연금 가입자 수는 근로기준법상 상시 근로자 수와 셈법이 달라 그대로 상시 근로자 수로 보기는 어렵다`

국민연금 가입자 수를 근거로 상시 근로자 수를 주장할 때에는 **어긋나는 방향(적게 나올 사유·많게 나올 사유)을 함께 적어** 상대방이 뒤집을 여지를 먼저 밝힌다.

## 8. 기록

조회한 사업자등록번호·사업장명·조회일·결과를 사건 폴더의 작업 기록에 남긴다. 사건 폴더가 없는 작업은 답변에 적는다. 사업자등록번호는 개인정보가 아니지만, 조회 결과를 사건과 무관한 곳에 옮기지 않는다.
