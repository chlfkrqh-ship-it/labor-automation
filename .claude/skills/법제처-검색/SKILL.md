# 법제처 OPEN API 검색

법제처가 자동 조회용으로 공개한 API이다. `공통/scripts/lawgo.py`로 부른다. 브라우저와 LBOX 계정을 쓰지 않으므로 `lbox-검색` 스킬의 본문 한도와 무관하다.

## 1. 처음 한 번 — 인증값과 IP 등록

1. 사용자가 [국가법령정보 공동활용](https://open.law.go.kr)에서 OPEN API 사용을 신청하고 **이 PC의 공인 IP**를 등록한다. 회사 PC와 집 PC처럼 IP가 다르면 모두 등록한다. 신청과 등록은 사용자가 직접 한다.
2. 사용자가 PC마다 한 번 인증값을 저장한다. `%LOCALAPPDATA%\노동사건자동화\lawgo.json`에 저장되고 OneDrive에는 올라가지 않는다. 인증값을 채팅에 받거나 대신 입력하지 않는다.

```powershell
python 공통/scripts/lawgo.py set-oc 인증값
python 공통/scripts/lawgo.py check
```

`check`가 "사용자 정보 검증에 실패하였습니다"를 내면 그 PC의 IP가 신청 정보에 등록되지 않은 것이다. 사용자에게 IP 등록을 요청하고 LBOX 검색만으로 진행하되, 법제처 검색을 하지 못했다는 사실을 검색기록에 적는다.

- **국세법령정보시스템 출처 판례는 목록에는 나오지만 API로 본문이 오지 않는다.** `harvest`는 이를 건너뛰고 건수만 알리며, `show`는 법제처 누리집 주소를 알려 준다. 필요하면 사람이 누리집에서 연다.
- 노동부해석은 원자료에 안건명과 질의요지가 어긋난 건이 있다. 회답 본문으로 판단한다.
- 행정규칙 가운데 내용이 첨부파일(HWP)에만 있는 것이 있다. 본문이 비거나 짧으면 `첨부파일` 칸의 주소를 사용자에게 알려 사람이 연다. 찾는 고용노동부 지침이 행정규칙으로 나오지 않으면 없는 것으로 단정하지 않고 고용노동부 누리집 자료를 사용자에게 요청한다.

## 3. 검색어 — LBOX와 다르다

| 검색어(판례 본문검색) | 결과 |
|---|---|
| `직장 내 괴롭힘` | 93 |
| `"직장 내 괴롭힘"` | 58 |
| `직장 내 괴롭힘 업무상 적정범위` | 14 |
| `"직장 내 괴롭힘" "업무상 적정범위"` | 1 |
| `업무상 적정범위` · `업무상적정범위` | 434 · 434 |

- **띄어 쓴 낱말은 모두 들어 있는 것만 남는다(AND).** LBOX는 네 낱말까지만 AND이고 다섯 낱말부터는 일부만 들어 있어도 걸린다(`lbox-검색` 1항). 낱말을 더하면 좁아지므로 LBOX용 따옴표 검색어를 그대로 넣으면 너무 좁아질 수 있다. 법제처에는 따옴표를 뺀 두세 낱말 검색어도 함께 넣는다.
- 큰따옴표는 구절 검색이다. **따옴표 안은 띄어쓰기까지 판결문과 같아야 한다**(`"통상임금"` 661건·`"통상 임금"` 30건, `"직장 내 괴롭힘"` 58건·`"직장내괴롭힘"` 2건). 따옴표 없는 낱말은 띄어쓰기를 무시한다(`통상임금`·`통상 임금` 모두 2,323건). 판결문에서 흔히 쓰는 띄어쓰기로 묶고, 헷갈리면 두 가지를 다 넣는다(2026. 9. 17. 실측).
- **`|`는 '또는'이다.** `괴롭힘 | 따돌림`은 349건으로 두 낱말 결과(194·204건)의 합집합과 같다. 낱말끼리만 쓴다. 따옴표 구절과 섞거나(`"직장 내 괴롭힘" | 따돌림` 112건으로 `따돌림`만 넣은 204건보다 적다) 다른 낱말과 섞으면 앞뒤 순서에 따라 결과가 달라진다. 빼기(`-`·`!`)·괄호·`*`는 작동하지 않는다.
- **쟁점마다 만드는 검색어는 `lbox-검색` 1항 '쟁점마다 만드는 검색어'와 같다.** 하위 쟁점마다 핵심 판시 구절 하나(따옴표)와 핵심 낱말 둘(띄어 쓰면 AND)을 기본으로 한다. 2026. 9. 17. 대법원 30건 시험에서 쟁점마다 이 두 개를 넣으면 77%였고, 같은 재료로 여덟 개까지 늘려도 81%였다. 사실관계 낱말을 바꿔 쓴 표현은 표현마다 핵심 낱말과 묶어 따로 넣고, 의뢰인 자료에 적힌 업종·설비·규정 이름도 바꾸지 않은 채 넣는다(`보수규정 성과상여금`·`임금규정 성과상여금`, `전기업 보험료율`). LBOX 실제 사건 시험에서 못 찾던 판례를 가장 많이 찾은 방법이다(`lbox-검색` 1항 4, 2026. 9. 18.). `|` 묶음은 다른 낱말과 섞으면 결과가 흔들리고, 묶음만 넣으면 결과가 1,300건 안팎으로 불어나 정답 비율이 0.5%였다.
- 기본 범위는 제목(사건명·안건명)이다. **판례·결정문은 `--body`(본문검색)를 붙인다.**
- 관련도 정렬이 없다. 기본은 최신순이다. 받은 목록 **전체**에서 사건명·요지로 거른다.

## 4. 명령

```powershell
# 여러 종류·검색어를 한꺼번에 받고 합친다. 결과는 파일로 쓰고 필요한 부분만 읽는다
python 공통/scripts/lawgo.py harvest --kinds 판례,노동위,노동부해석,산재재심사 --query "직장 내 괴롭힘" --query "업무상 적정범위 괴롭힘" --body --limit 300 --texts 30 --out "{사건}/라운드N/작업/법제처"

python 공통/scripts/lawgo.py search 판례 "직장 내 괴롭힘" --body --court 대법원 --out 목록.json
python 공통/scripts/lawgo.py search 판례 --number 2020다270503
python 공통/scripts/lawgo.py show 판례 228521 --out 본문.md

# 법령 조문. 법령명은 띄어쓰기를 빼거나 약칭(남녀고용평등법)으로 적어도 찾는다
python 공통/scripts/lawgo.py article 근로기준법 76의2
python 공통/scripts/lawgo.py article 근로기준법 76의2 --date 20190801
python 공통/scripts/lawgo.py article "근로기준법 시행령" 6
python 공통/scripts/lawgo.py search 법령 근로기준법 --history

# 행정규칙
python 공통/scripts/lawgo.py search 행정규칙 --org 고용노동부 --rule-kind 예규 --limit 100 --out 목록.json
python 공통/scripts/lawgo.py search 행정규칙 통상임금 --body --org 고용노동부
python 공통/scripts/lawgo.py show 행정규칙 2100000029603

# 국가인권위 결정문(직장 내 괴롭힘·차별)
python 공통/scripts/lawgo.py search 인권위 "직장 내 괴롭힘" --limit 50
python 공통/scripts/lawgo.py show 인권위 307 --out 인권위_307.md

# 별표·서식. 본문 대신 한글·PDF 파일을 내려받는다
python 공통/scripts/lawgo.py search 별표 "신체장해의 등급" --limit 20
python 공통/scripts/lawgo.py file "https://www.law.go.kr/LSW/flDownload.do?flSeq=165011921" --out "공통/캐시/법제처/별표.hwp"
```

- `harvest`는 종류마다 검색어별 결과를 합치고(같은 판결이 출처별로 두 번 오면 하나로), 여러 검색어에 걸린 것 → 전체 건수가 적은(좁은) 검색어에 걸린 것 → 최신순으로 줄 세운다. `--texts N`은 그 순서로 N건의 본문을 받아 `법제처_본문_{종류}.md`에 쓰고, 요약의 `본문목록`에 받은 본문의 법원·사건번호·사건명을 적는다. 목록 전체는 `법제처_목록.json`에 쓴다.
- **받은 본문으로 인용 순위를 함께 낸다.** 본문들이 함께 인용한 판례를 인용한 판결 수 순서로 세워 `인용순위_상위`(요약)와 `법제처_목록.json`의 `인용순위`에 쓴다. `목록 밖`으로 표시된 상위 판례는 검색어가 놓친 지도적 판례일 가능성이 높으므로 `search 판례 --number`로 찾아 먼저 읽는다. **`--texts`는 20 이상으로 한다.** 2026. 9. 17. 대법원 노동 판결 30건의 참조판례 110건으로 잰 결과, 구절 검색 목록만으로 65%, 목록 상위 20건 본문의 인용 순위를 더하면 83%를 찾았고, 인용 순위 상위 20건 안에 63%가 들었다(10건만 읽으면 59%, 합계 82%). 순위 상위 판례를 한 번 더 따라가는 2단계 확장은 늘지 않았다. 인용 순위는 대법원 법리를 보태는 데 쓰고, 사실관계가 비슷한 하급심은 검색어(3항의 사실관계 표현)로 찾는다(실제 사건 시험에서 순위에 오른 정답은 모두 대법원 판결이었다). 자세한 수치는 `lbox-검색` 3항 '인용 순위', 다시 재는 방법은 `공통/검증/판례검색/README.md`.
- **인용 순위를 쓰기 전에 `본문목록`으로 받은 본문이 쟁점과 맞는 판결인지 본다.** 법제처 본문검색은 낱말이 판결 어디에든 있으면 걸리므로, 넓은 낱말 검색어를 섞으면 무관한 판결이 목록 앞에 온다. 2026. 9. 17. KEPS 사건 시험에서 `위탁운영 사업종류` 같은 검색어 7개로 전체 법원 판례를 받자(국세 판례를 뺀 342건, 그중 사건명이 보험료·산재·사업종류 사건인 것 82건) 본문 20건 중 17건이 형사·근로자지위 판결이었고 인용 순위에도 형사 판례가 섞였다. 목록 정렬에 좁은 검색어를 넣은 뒤로는 상위 20건 중 주제 사건이 3건에서 11건으로 늘었다. **사건 종류가 사건명에 드러나는 쟁점(보험료 부과처분, 부당해고 구제 재심판정 등)은 `--texts-title`로 본문을 고른다.** 같은 시험에서 `--texts-title 보험료,산재,사업종류,보험급여,징수`를 주자 본문 20건이 모두 그런 사건이었고, 인용 순위 상위가 KEPS 세션이 LBOX 인용 순위로 얻은 판례(대법원 2002두10582, 2009두16169)와 겹쳤다. 목록은 거르지 않으므로 사건명이 다른 판결도 목록에서 따로 본다. 그래도 본문이 절반 넘게 무관하면 그 인용 순위는 쓰지 않고, 판시 문구에 가까운 구절로 검색어를 바꾸거나 `--court 대법원`으로 좁혀 다시 받는다.
- 근로복지공단산재판례 출처는 목록에 법원·사건번호·선고일이 비어 온다. 본문(`show`)에는 사건번호와 법원이 들어 있었으므로(2026. 9. 17. 1건 확인) 인용할 것은 본문으로 확인한다.
- `--court 대법원|하급심`, `--source`는 판례에만, `--period 20200101~20221231`은 판례·헌재·법령해석·행정심판·노동부해석·법령·행정규칙에만 쓴다. `--org`(고용노동부 또는 숫자 코드)는 법령·행정규칙에, `--rule-kind`(훈령·예규·고시·공고·지침·기타)는 행정규칙에만 쓴다. `--history`는 법령이면 연혁·시행예정 판본까지, 행정규칙이면 연혁만 받는다.
- `article`은 조문 하나를 받는다. `--date`를 주면 그날 시행 중이던 판본을 골라 받고, 그 판본에 없던 조문이면 오류로 알린다(예: 근로기준법 제76조의2는 2019. 1. 1. 기준 없음, 2019. 8. 1. 기준 2019. 7. 16. 시행 판본). `show 법령`에는 법령일련번호를 넘기며 법령 전체(조문·부칙·별표)가 온다.
- 사건 폴더가 없는 `/판례검색`·`/서면보강`은 `--out 공통/캐시/법제처/{날짜}_{주제}`에 쓴다. 라운드가 없는 `/검토의견`은 `--out "1_검토의견/사건/{의뢰인}_{검토내용}/법제처"`에 쓴다.
- 받은 본문은 `%LOCALAPPDATA%\노동사건자동화\캐시\lawgo\`에 보관하여 같은 문서는 다시 요청하지 않는다. `show --refresh`로만 다시 받는다.
- **별표·서식(`별표`·`행정규칙별표`)은 `show`가 막혀 있다.** 본문 조회가 JSON이 아니라 뷰어 HTML로 오기 때문이다(2026. 9. 20. 실측). 목록의 `한글파일`·`PDF파일` 주소를 `file` 명령으로 내려받아 읽는다. 별표번호는 `000300`이 `별표 3`, `000302`가 `별표 3의2`로 풀린다.
- **별표 검색어는 별표 이름에 걸린다.** 관련 법령명으로는 걸리지 않는다(`근로기준법` 0건, `신체장해 종합평가 등급표` 7건). 찾는 표의 이름을 그대로 넣는다.
- **`school`(학칙·공단·공공기관 규정)은 넣지 않았다.** 이름과 달리 국립대학교 규정만 있고 공단·공공기관 규정은 `공단`으로 검색해도 0건이다(2026. 9. 20. 실측). 공공기관 인사규정·보수규정은 사건 자료로 받는다.
- 한 건씩 차례로 보내고 호출 사이 0.3초를 둔다. 공식 API이지만 몰아서 보내지 않는다.

## 5. LBOX와 나누어 쓰는 법

- **같은 쟁점을 양쪽에서 받는다.** LBOX 수확(`lbox-검색` 4항)과 같은 때에 법제처 `harvest`를 돌린다. 어느 쪽이 더 많은지를 이유로 한쪽을 건너뛰지 않는다. 지난 사건들에서 실제로 인용한 판례(`공통/판례기록`) 가운데 법제처에 있는 것은 대법원 119건 중 85건(71%), 하급심 36건 중 1건(3%)이었다(2026. 9. 17.). 대법원 판결도 열에 셋은 법제처에 없고(심리불속행 기각 판결 등), 하급심은 사실상 LBOX에만 있다. 거꾸로 법제처가 LBOX를 메우기도 한다. 2026. 9. 19. 사건 16건(정답 210건)에서 같은 기본 검색어로 받은 법제처 판례 목록이 LBOX 목록에 없던 정답 11건을 보탰고, 모두 대법원 판결이었다(`공통/검증/판례검색/결과_2026-09-19_새범주.json`).
- **법제처에 있는 판례 본문은 법제처에서 먼저 읽는다.** LBOX 본문 한도는 법제처에 없는 하급심·대법원 판결과 결정례에 쓴다. 법제처 목록의 `lbox` 칸은 법원명·사건번호로 만든 LBOX 주소이다.
- **대법원 판결을 찾으면 LBOX 인용망 검색으로 이어 간다.** 법제처에서 찾은 사건번호를 따옴표로 묶어(`"2020다270503"`) LBOX에서 검색하면 그 판결을 따른 하급심이 나온다(`lbox-검색` 3항 ①).
- **노동위원회 판정요지·고용노동부 행정해석·재심사위원회 결정은 법제처가 넓다.** LBOX 결정례·유권해석 탭과 함께 보고, 서로 없는 것을 보탠다.
- **인용 전 확인과 하이라이트는 그대로 한다.** 인용할 판례는 `lbox-검색` 5항대로 LBOX 원문에서 확정 여부·상하위 판결을 보고 `lbox-하이라이트`로 칠한다. `lbox` 주소는 추정이므로 열어서 확인한다. LBOX에 없는 자료(노동위원회 판정요지·행정해석 등)는 칠할 원문이 없으므로 답변 말미에 법제처 일련번호와 인용 위치를 적는다.
- **재결·판정문은 주장과 판단을 나누어 읽는다.** 행정심판 재결은 '청구인 주장'·'피청구인 주장'·'인정사실'·'판단'이 한 본문에 이어져 오고, 법제처 본문에는 LBOX 화면과 달리 항목 구분이 눈에 띄지 않는다. 인용할 문장이 어느 항목에 있는지 확인하고, 주장 부분을 위원회의 판단으로 쓰지 않는다(루트 공통 규칙 '판결·결정문 속 당사자 주장을 법원 판단처럼 인용하지 않는다'). 2026. 9. 17. 재결 2009-13291의 피청구인 주장 부분을 재결례의 판단처럼 인용한 일이 있었다.
- 행정해석은 `1_검토의견` 지침의 인용 형식대로 쓴다(예: `(근로기준정책과-3084, 2015. 7. 13.)`).
- **서면·검토의견에 옮기는 조문은 `article`로 받아 원문 그대로 옮긴다.** 기억이나 판례 속 인용문으로 조문을 적지 않는다. 해고일·임금 청구 기간처럼 사건 당시의 법령이 문제되면 `--date`로 그날 시행 중이던 조문을 받고, 현행과 다르면 '구 근로기준법(2019. 1. 15. 법률 제16270호로 개정되기 전의 것)'처럼 판본을 밝힌다.

## 6. 기록

`lbox-검색` 7항 검색기록 표에 함께 적는다. 탭 칸에는 `법제처-판례`·`법제처-노동위`처럼 쓰고, 받은 건수와 본문까지 읽은 건수를 같은 표에 적는다. 표 아래 줄에 `법제처 호출 N회`(harvest 결과의 `호출`)와 본문을 받지 못한 건수·사유(`본문실패`, `국세판례_본문미제공`)를 덧붙인다.

'판례가 확인되지 않는다'고 쓰기 전에 LBOX뿐 아니라 법제처 검색도 했는지 이 표로 점검한다. 인증·IP 문제로 법제처 검색을 못 했으면 그 사실을 적는다.
