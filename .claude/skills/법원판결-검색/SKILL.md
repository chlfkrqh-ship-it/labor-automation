# 법원 누리집 판결 게시판 검색

LBOX 가 2026. 11. 11. 자동화 수단 금지(이용약관 제11조)를 들어 계정을 제한하여 멈춘 동안(`lbox-검색` 맨 앞 '사용 중지') 하급심을 보태는 경로이다. 판례 검색의 중심은 `법제처-검색`(법제처 OPEN API)이고, 이 스킬은 그와 같은 때에 함께 돌린다. 어느 업체·누리집을 왜 쓰고 왜 안 쓰는지는 `공통/판례출처.md` 에 있다.

## 1. 무엇이 있는가

2026. 11. 11. 실측이다.

| 게시판(명령에 쓰는 이름) | 싣는 것 | 규모 | 첨부 |
|---|---|---|---|
| 주요판결(전국법원 주요판결) | 각급법원이 고른 하급심 판결. 제목 끝에 사건번호, 본문에 '○ 법원 날짜 선고 번호 판결'·사실관계·재판부 판단 요지 | 23,742건 | 비실명 판결문 PDF. **글자층이 없는 것이 많아**(글을 선으로 그린 PDF) Windows 문자인식으로 읽는다 |
| 판례속보 | 법원도서관의 대법원 중요판결 요지(제목 끝 '[대법원 날짜 선고 중요판결]'), 판례공보·각급법원 판결공보 요약본 | 11,314건 | 판결문 hwpx·PDF(글자층 있음) |

- **게시판은 법원·법원도서관이 고른 판결만 싣는다.** 여기서 찾지 못한 것을 근거로 '판례가 확인되지 않는다'고 쓰지 않는다(루트 `CLAUDE.md` '근거를 찾지 못한 쟁점'). 검색기록에 이 경로로 본 범위(게시판·검색어·건수)를 적고, 찾지 못한 하급심은 `lbox-검색` 맨 앞대로 담당자에게 검색어와 사건번호를 알린다.
- **게시판 본문은 법원·법원도서관이 쓴 요지이지 판결의 판단이 아니다.** 인용은 첨부 판결문의 이유 중 판단에서 한다(루트 `CLAUDE.md` '판결·결정문 속 당사자 주장을 법원 판단처럼 인용하지 않는다'). 결과 파일도 요지를 '게시판 본문'으로 따로 적는다.
- **확정 여부는 주요판결·언론보도 게시물에 적혀 있지 않다.** 공보 색인에 있는 하급심은 `공보찾기` 로 확정·항소·상고 표시를 본다. 색인에 없으면 판결문의 기재나 나의사건검색(보안문자는 담당자)으로 보고, 확인하지 못하면 대조표 '확정' 칸에 '확인 못함'과 다시 본 날짜를 적는다(`공통/자체검토.md` 3절). 공보 표시는 요약본을 낸 때의 것이므로 그 뒤 상급심이 났을 수 있다. 미확정으로 나온 판결은 넘기기 전에 다시 본다.

- 종합법률정보(portal.scourt.go.kr)는 넣지 않았다. 화면 코드에 '로봇탐지 솔루션 적용'과 매크로 판정 칸이 있어 운영자가 자동 이용을 막고 있다. 같은 대법원 판례정보가 법제처 OPEN API 로 오므로 `법제처-검색` 으로 갈음한다. 담당자가 화면에서 쓰는 것은 막지 않는다.
- 법고을은 로그인·약관 링크·robots.txt 가 없고 화면 코드에 로봇 탐지가 없어 넣었다(2026. 11. 11. 담당 노무사 "여기도 쓰자"). 판례 자료가 법제처와 같으므로 harvest 가 함께 돌려 맞대는 몫이고, 법제처가 막힌 날의 예비 경로이다. 다시 훑기는 법제처 줄과 사건번호가 같은 법고을 줄을 한 줄로 둔다. 문헌 원문은 저작권회원 로그인이 필요해 쓰지 않는다.

## 2. 검색어 — 제목에서 글자열로 찾는다

- **게시판 검색은 게시물 제목에서 띄어쓰기까지 같은 글자열을 찾는다.** 본문은 찾지 않고, 띄어 쓴 낱말을 AND 로 걸지 않는다(주요판결 '직장 내 괴롭힘' 11건, '괴롭힘 징계' 0건, 본문에만 있는 '부진정연대채무'로는 그 글이 걸리지 않았다).
- 그래서 **제목에 쓰일 낱말 하나나 붙어 다니는 짧은 구절을 여러 개** 넣는다(`강등`·`정직`·`이중징계`, `직장 내 괴롭힘`·`괴롭힘`·`징계양정`·`양정`). 여러 검색어에 걸린 글이 목록 앞에 온다. 법제처·LBOX 용 따옴표 검색어를 그대로 넣지 않는다.
- 주요판결 제목은 '[행정][노동] …한 사안(서울행정법원 2025구합300)'처럼 쟁점을 풀어 쓴다. 사건 종류 낱말(`해고`·`징계`·`임금`·`산업재해`)과 사안 고유어(`요양원`·`발전소`)를 섞는다.
- 공보 색인은 **사건명**(징계결정취소, 임금, 유족급여및장의비부지급처분취소)에서 찾으므로 사건 종류 낱말로만 걸린다. 주제 검색보다 사건번호로 확정 표시를 찾는 데 쓴다.

## 3. 명령

```powershell
# 여러 검색어로 세 게시판과 공보 색인을 훑어 법원_목록.json 을 쓴다(법제처_목록.json 과 같은 칸)
python -B 공통/scripts/scourt.py harvest --query 강등 --query 정직 --query 이중징계 --views 40 --texts 5 --out "{사건}/라운드N/작업/법원"

python -B 공통/scripts/scourt.py search 주요판결 "직장 내 괴롭힘" --limit 30          # 목록만
python -B 공통/scripts/scourt.py search 법고을 "강등 정직" --limit 100                  # 법고을 판례(판결 전문에서 AND)
python -B 공통/scripts/scourt.py search 주요판결 해고 --court 서울행정법원             # 주요판결은 올린 법원으로 거를 수 있다
python -B 공통/scripts/scourt.py show 주요판결 28730                                   # 게시물 하나(요지·첨부 주소)
python -B 공통/scripts/scourt.py get 주요판결 28730 28729 --out "{사건}/라운드N/작업/법원"  # 첨부 판결문을 받아 글을 뽑는다
python -B 공통/scripts/scourt.py 공보 --limit 300                                       # 각급법원 판결공보 요약본 색인을 만들거나 잇는다
python -B 공통/scripts/scourt.py 공보찾기 2025구합54661 2025가합200819                  # 확정·항소·상고 표시(요청 없음)
python -B 공통/scripts/scourt.py usage                                                  # 오늘 요청 수·멈춤 표시
```

- `harvest` 의 기본 게시판은 주요판결·판례속보·언론보도·공보·법고을이다. 법고을은 법제처처럼 판결 전문에서 낱말을 AND 로 찾으므로 법제처용 검색어(따옴표 없는 두세 낱말)를 쓰고, 게시판은 2항의 제목 낱말을 쓴다. 둘을 나누려면 `--boards` 를 따로 주어 두 번 돌린다.
- `harvest` 는 게시판마다 검색어별 목록을 끝 쪽까지 받아 합치고, 여러 검색어에 걸린 것 → 전체 건수가 적은 검색어에 걸린 것 → 최신 순으로 세운다. 앞의 `--views` 건(기본 40)은 게시물을 열어 제목 전문·법원·선고일·사건번호·요지·첨부를 채우고, 열지 않은 줄은 사건번호가 비어 있다(목록 제목은 '…'로 잘린다). `--texts` 건은 첨부 판결문을 `{out}/판결문/` 에 받아 글을 `{out}/법원_본문_{게시판}.md` 에 쓴다. 요약에 게시판별 하급심·대법원 건수가 나온다(언론보도는 사건부호로 심급을 매긴다).
- **받은 판결문의 글 출처를 본다.** `글자층`·`hwpx` 는 그대로 읽어도 되나, `문자인식` 은 낱자가 틀릴 수 있다(2026. 11. 11. 시험: '2026. 10. 8.까지'가 '10. &까'로 읽혔다). 인용할 문장은 `판결문/` 의 PDF 를 그 면의 그림으로 열어 맞대어 옮기고, 대조표 '원문' 칸에 PDF 경로와 '문자인식 대조(날짜)'를 적는다.
- 사건 폴더가 없는 `/판례검색`·`/서면보강` 은 `--out 공통/캐시/법원/{날짜}_{주제}` 에 쓴다. 라운드가 없는 `/검토의견` 은 `--out "1_검토의견/사건/{의뢰인}_{검토내용}/법원"` 에 쓴다. `--out` 은 폴더 이름이다(파일 이름을 주면 멈춘다). 폴더 이름은 `법원` 이나 `법원_…` 으로 한다. `harvest_titles.py` 가 그 이름을 수확 폴더로 보아 기록에서 뺀다.

## 4. 지키는 것(스크립트가 막는다)

- 요청은 한 번에 한 건, 앞 요청과 4.5초 넘게 띄운다. 하루 상한은 500건이다(`SCOURT_DELAY`·`SCOURT_DAILY_MAX` 로 바꾼다. 바꾸는 것은 담당자가 정한다). 같은 법원 전산망이 전자소송·나의사건검색을 함께 운영하므로, 몰아서 보내다 사무실 IP 가 막히면 전자소송까지 막힐 수 있다.
- 요청 전에 그 호스트의 robots.txt 를 하루 한 번 받아 가장 긴 규칙으로 판정하고 막힌 주소는 보내지 않는다. **첨부 내려받기 주소(file.scourt.go.kr/AttachDownload)는 robots.txt 가 막는다.** 스크립트는 허용된 폴더 주소(file.scourt.go.kr/dcboard/·/nboard/, www.scourt.go.kr/sjudge/)로만 받는다. 2004년 무렵 옛 게시물처럼 허용 폴더를 모르는 첨부는 받지 않고 '사람이 화면에서 받는다'로 남긴다.
- 403·429·503 이나 차단·자동입력 확인 화면이 오면 곧바로 멈추고 `%LOCALAPPDATA%\노동사건자동화\캐시\scourt\중단.txt` 를 남긴다. 그 파일이 있으면 다시 보내지 않는다. **확인 항목을 대신 누르거나 파일을 지워 다시 돌리지 않고** 담당자에게 멈춤 표시의 글을 그대로 알린다. 담당자가 누리집을 열어 확인한 뒤 지운다.
- 받은 목록은 그날만, 게시물·파일은 계속 캐시에 두고 다시 요청하지 않는다(`show --refresh` 로만 다시 받는다).

## 5. 법제처·LBOX 와 나누어 쓰는 법

- **같은 쟁점을 법제처와 함께 받는다.** 법제처 `harvest` 와 같은 때에 돌리고, 한쪽이 많다고 다른 쪽을 건너뛰지 않는다. 2026. 11. 11. 실제 쟁점 둘로 잰 결과이다(`공통/판례출처.md` 4절).

| 쟁점 | 법제처 판례 본문검색 | 법원 누리집 세 게시판 |
|---|---|---|
| 강등·정직·이중징계 | 66건(대법원 20, 하급심 42 = 64%, 공단 산재판례 4) | 71건(하급심 53 = 75%, 대법원 17). 사건번호를 확인한 37건 가운데 법제처 수확 목록에 없는 하급심 20건, 그 가운데 15건은 법제처에 사건번호로도 없다. 겹친 번호 2건(모두 대법원) |
| 직장 내 괴롭힘 징계 양정 | 31건(대법원 2, 하급심 8, 공단 산재판례 21) | 51건(하급심 39 = 76%, 대법원 10). 사건번호를 확인한 30건 가운데 법제처 수확 목록에 없는 하급심 20건, 20건 모두 법제처에 사건번호로도 없다. 겹친 번호 0건 |

- 법제처는 대법원 법리와 인용 순위(참조판례)를 맡고, 법원 누리집은 사실관계가 비슷한 하급심을 보탠다. 법원 누리집의 대법원 글(판례속보·언론보도)은 법제처 본문으로 다시 읽는다(법제처에 있으면 그것이 원문 대조의 기준이다).
- 찾은 하급심 사건번호로 법제처 `search 판례 --number` 를 돌려 본문이 법제처에도 있는지 본다. 있으면 법제처 본문으로 읽고 인용한다.
- 게시판에서 찾은 판결의 상급심·하급심은 게시물에 없다. 판결문 머리(원심 판결 표시)와 공보 색인으로 잇고, 모르면 담당자에게 사건번호를 알린다.

## 6. 기록

- `lbox-검색` 7항 검색기록 표에 `법원-주요판결`·`법원-판례속보`·`법원-언론보도`·`법원-공보` 탭으로 검색어·전체 건수·받은 건수·연 게시물 수·받은 판결문 수를 적고, 표 아래에 `법원 누리집 요청 N회`(harvest 결과의 `호출`)와 받지 못한 첨부·사유를 적는다.
- LBOX 를 멈춘 동안 최종 관문은 LBOX 목록 대신 검색기록의 'LBOX 중지' 줄과 `법원_목록.json` 을 본다. 누리집을 쓰지 못한 날(점검·멈춤 표시·상한)은 검색기록에 `법원 누리집 못 봄: {사유}` 를 적는다(`final_check.py` '판례 검색 기록').
- 수확 목록 다시 훑기(`harvest_titles.py scan`)는 `법원_목록.json` 의 줄도 읽는다. 게시물을 열지 않은 줄은 '번호 없음'으로 나오므로 처리 칸에 무엇을 하였는지 적는다(열어 보거나 '제목상 사안 다름: …').
