# 4_서면작성

준비서면·이유서·답변서·재심이유서를 라운드별 공방 구조로 작성한다. **산출물은 서면 본문 .docx 와 그 서면에 딸린 제출용 증거 묶음이다.** 판례를 나열만 하는 작업은 `2_판례검색`, 사용자가 이미 쓴 서면을 보강하는 작업은 `3_서면보강` 이다.

하이라이트 색은 **연두**(`rgb(163,230,53)`, 팔레트 2번)이다.

## 1. 폴더 배치

```
4_서면작성/
├─ skills/노동서면작성/           ← SKILL.md(문장 규칙·금지·자가점검)와 references/(문체·표기·인용·구성)
├─ templates/                     ← 표준양식.docx, 문서서식.md, 스타일가이드.md, 문체레퍼런스
├─ scripts/                       ← docx_merge.py, docx_restyle.py, docx_footnotes.py, docx_normalize.py
└─ 사건/{사건명}/
   ├─ 증거관리/우리호증목록.md, 상대호증목록.md
   ├─ 노동위원회_기록/우리서면, 상대서면, 증거   ← 행정소송 사건만
   └─ 라운드N/
      ├─ 우리증거/, 상대증거/      ← 원자료를 넣는 자리
      ├─ 발췌/                     ← 본문에 넣을 증거 발췌 이미지
      ├─ 작업/                     ← 사실관계_정리.md, 상대주장분석.md, 반박포인트.md
      └─ 출력/                     ← 서면_프레임.docx, 서면초안.md, ({의뢰인명}) {서면명}_초안.docx
         └─ 제출/                  ← 제출 형태로 변환한 사본. 서면 + 증거/ 호증별 PDF
```

**경로는 저장소 루트 기준 상대경로로 쓴다.** 이 폴더는 OneDrive 안에 있고 PC마다 절대경로가 다르다. 사용자가 사건명만 적으면 `4_서면작성/사건/{사건명}` 으로 읽는다.

새 사건은 `4_서면작성/사건/_템플릿` 을 복사해서 만든다. 라운드를 늘릴 때는 직전 라운드 폴더를 복사한다.

## 2. 명령어

| 명령어 | 하는 일 |
|---|---|
| `/증거정리 {사건명} 라운드N` | 우리증거·상대증거에 호증번호를 부여하고 증거관리/ 목록에 올린다 |
| `/서면 {사건명} [라운드N]` | 서면 초안을 만든다. **서면 종류는 프레임 표지가 정하고**, 자료에 따라 아래 절차를 함께 켠다 |
| `/문체검증 {파일}` | 완성된 초안을 문체 규칙으로 실측 채점한다 |

서면 종류는 준비서면·항소이유서·재심이유서·참고서면·청구원인·석명준비명령 답변·변호인의견서 등 여럿이고, **`출력/서면_프레임.docx` 표지의 서면명과 당사자 표시가 이를 정한다.** 폴더 이름이나 증거에 판정서·판결문이 있다는 사실로 판단하지 않는다. 자료 상태에 따라 아래 두 절차를 함께 적용한다. 서면 종류와 다른 축이므로 둘 다 켜질 수 있다.

| 자료 | 함께 적용할 절차 |
|---|---|
| 사건 폴더에 `노동위원회_기록/` 이 있다 | `4_서면작성/절차/노동위기록-추출.md` |
| 대상 라운드 `상대증거/` 에 상대방 서면이 있다 | `4_서면작성/절차/반박-구성.md` |

`/서면` 은 증거관리/ 호증목록이 최신이라는 전제로 돈다. **초안을 쓰기 전에 증거정리를 스스로 먼저 한다.** 대상 라운드의 `우리증거/`·`상대증거/` 에 호증번호가 없는 자료가 있거나 호증목록이 비어 있으면, `.claude/commands/증거정리.md` 의 절차를 이 작업 안에서 수행하고 목록을 갱신한 뒤 초안을 쓴다. 사용자가 `/증거정리` 를 따로 불러 주기를 기다리지 않는다. 새로 부여한 호증번호는 초안을 쓰기 전에 보고한다.

호증번호를 이미 부여해 두었더라도 **그 결과가 `증거관리/` 의 호증목록에 올라와 있는지 확인한다.** 파일명에만 번호가 붙어 있고 목록이 비어 있으면 서면과 목록이 어긋난 채로 제출된다(2026. 9. 10. GGM 경영설명회 사건에서 실제로 발생: 갑 제1~38호증이 편철되어 있었으나 목록은 빈 표였다).

**편철한 파일의 표제와 내용이 실제로 맞는지 전수 확인한다.** 호증목록의 번호가 맞아도 파일 안이 다른 문서일 수 있다. 노동위 합본 PDF를 호증별로 나눈 자료를 옮겨 편철할 때 특히 그렇다(2026. 9. 16. 이케아 부당해고 사건에서 실제로 발생: 호증 도장이 찍힌 첫 장이 앞 호증 파일 끝에 붙는 경계 어긋남 때문에 갑 제21·22·35·43호증의 표제와 내용이 어긋난 채 소장과 함께 제출되었다). 절차와 검증 명령은 `.claude/commands/증거정리.md` 의 '호증 경계 확정과 편철 검증' 에 있다.

## 2-1. 제출 묶음 (서면과 함께 낸다)

**서면 docx 를 만들면 그것으로 끝이 아니다.** 인사위원회나 재판부에 낼 때 서면만 가는 일은 없고 증거가 함께 간다. `라운드N/출력/제출/` 에 **제출 형태로 변환한 사본**을 모은다. 원자료는 `우리증거/` 에 그대로 둔다(2026. 9. 16. 황도윤 징계 사건 담당자 지시: 최종서면을 내면서 증거를 zip·xlsx·png 원자료 상태로 두어 그대로는 제출할 수 없었다).

```
라운드N/출력/제출/
├─ 0_먼저 읽기.md      ← 변환 내역, 남은 상태, 사람이 할 일
├─ ({의뢰인명}) {서면명}_초안.docx   ← 출력/ 의 서면 사본(3-1절). PDF도 같은 이름으로 함께 둔다
└─ 증거/
   └─ {호증번호}_{자료명}.pdf
```

**호증 하나에 파일 하나, 전부 PDF, 전부 A4 세로로 맞춘다.**

- 사진 묶음(zip)은 **면 순서를 사람이 정해서** 한 PDF로 합친다. 표지·목차가 있으면 앞에 둔다. 파일명 숫자순으로만 정렬하면 표지가 뒤로 간다.
- 누워서 찍힌 스캔본은 세운다. **화면 캡처는 가로로 길어도 회전하지 않는다.** 폭이 높이보다 크다는 이유로 일괄 회전하면 메일 캡처가 눕는다.
- xlsx·docx 원본은 LibreOffice 로 PDF 변환한다.
- 변환이 끝나면 `evidence_check.py sheet` 로 첫 면 모음을 만들어 **모든 칸의 표제와 내용을 눈으로 본다.** 이 단계에서 회전 오류와 표제 어긋남이 잡힌다.
- 원자료에 호증 도장이 없으면(사진·캡처가 원본인 경우) 그 사실을 `0_먼저 읽기.md` 와 호증목록 비고에 적는다. 도장을 그려 넣지 않는다.
- **서면이 최신이 아니면 제출 폴더에 넣지 않는다.** 잠금 등으로 병합이 실패했으면 서면 자리를 비워 두고 그 사유를 `0_먼저 읽기.md` 에 적는다. 낡은 서면이 제출 묶음에 남아 있는 것이 가장 위험하다.

## 2-2. 프레임 표지 — 법원 서면과 노동위원회 서면

`사건/_템플릿` 의 프레임과 `templates/표준양식.docx` 는 **법원 서면 기준**이다(표준양식은 피고보조참가인 소송대리인 표기이다). 노동위원회 구제신청·재심 사건은 표지를 아래대로 바꾼 뒤 초안을 쓴다. 표지 한 줄만 다른 것이 아니라 일곱 자리가 갈린다.

| 자리 | 법원 서면 | 노동위원회 서면 |
|---|---|---|
| 표지 상단 기일 표 | 기일·주심 표를 둔다 | 표를 지운다 |
| 사건칸 | 사건번호 | 사건번호 + `부당정직 및 부당노동행위 구제신청 사건` 등 사건명 |
| 당사자 라벨 | 원 고 / 피 고 / 피고보조참가인 | 신청인 / 피신청인 (재심은 재심신청인 / 재심피신청인) |
| 본문 첫 문장 | `…의 소송대리인은 … 제출합니다` | `…의 대리인은 … 제출합니다` |
| 서명 블록 첫 줄 | `[당사자] 소송대리인` | `대리인` |
| 담당자 | 담당변호사 강 민 석 · 이 수 진 · 김 현 수 | 담당변호사 강 민 석 · 이 수 진, 담당노무사 최 락 보 |
| 제출처(누름틀 `제출처`) | `서울행정법원 제1부 귀중` | `전남지방노동위원회 귀중` |

**'소송대리인'은 법원 서면에만 쓴다.** 노동위원회에는 공인노무사도 대리인으로 선임되므로 '대리인'으로 적는다(2026. 9. 22. GGM 정직 3월 답변서에서 담당자 지적. 그 사건 파일 2건은 그때 고쳤다).

`/서면` 은 프레임을 읽는 단계에서 제출처를 확인하고, 노동위원회 사건인데 위 자리가 법원 표기로 남아 있으면 고친 뒤 무엇을 고쳤는지 보고한다. 제출처를 자료에서 알 수 없으면 사용자에게 먼저 묻는다. 병합을 마친 docx 는 `python 4_서면작성/scripts/style_check.py <파일>` 로 확인한다. 제출처가 노동위원회인데 '소송대리인'이 남아 있으면 위반으로 잡힌다.

## 3. 작업 순서

1. 대상 라운드를 정한다. 사용자가 지정하지 않으면 가장 마지막 라운드로 한다.
2. `공통/사건상태.md`에 따라 자료 목록과 변경분을 확인한다. 최초 분석 또는 검증된 사건상태가 없을 때는 현재 라운드의 우리·상대 자료, 이전 라운드의 초안·사실관계·상대 자료, 호증목록을 모두 읽는다. 검증된 상태가 있으면 신규·변경 자료와 관련 원문을 읽고, 실제 인용과 입장 모순 여부는 원문으로 확인한다.
3. 호증목록이 최신인지 확인하고, 아니면 증거정리를 먼저 한다(2절). 작업/사실관계_정리.md 를 갱신하고, 상대방 서면이 있으면 작업/상대주장분석.md 를 만든다.
4. `4_서면작성/skills/노동서면작성/SKILL.md` 와 그 `references/` 의 모든 파일을 읽고 출력/서면초안.md 를 쓴다.
5. 출력/서면_프레임.docx 가 있으면 병합해서 `출력/({의뢰인명}) {서면명}_초안.docx` 를 만든다(3-1절).

## 3-1. 서면 파일 이름

**`({의뢰인명}) {서면명}_초안.docx` 로 짓는다. 의뢰인명은 소괄호로 감싼다.** 예: `(GGM) 답변서_초안.docx`, `(이케아) 준비서면_초안.docx`. 2026. 9. 22. 담당자 지시로 종전의 `최종서면.docx` 를 대신한다.

- **의뢰인명**은 우리가 대리하는 당사자의 짧은 이름이다. 사건 폴더 이름의 앞머리(`GGM_정직3월` → `GGM`)를 그대로 쓰고, 그것으로 알 수 없으면 사용자에게 묻는다.
- **서면명**은 프레임 표지의 서면명이다. 답변서, 준비서면, 재심이유서, 항소이유서 등.
- **수정 단계는 뒷말로 잇는다.** `_초안` → `_1차 수정안` → `_2차 수정안` 순이다. 담당자가 고쳐 돌려준 뒤 그 위에 다시 작업하면 다음 단계 이름으로 저장하고, 앞 단계 파일은 지우지 않는다.
- 제출 폴더의 사본과 PDF도 같은 이름을 쓴다.
- `docx_merge.py` 는 폴더만 주면 `최종서면.docx` 로 저장하므로, 이름을 지정하려면 세 인자 형태로 부른다.
  ```
  python 4_서면작성/scripts/docx_merge.py <프레임.docx> <초안.md> "<출력폴더>/({의뢰인명}) {서면명}_초안.docx"
  ```

## 4. LBOX

**검색은 루트 `lbox-검색` 스킬을 따른다.** 이 폴더 안에 검색 규칙 문서를 따로 두지 않는다. 규칙이 두 벌로 갈리면 한쪽만 고치게 된다.

인용한 판례·결정례·유권해석에는 루트 `lbox-하이라이트` 스킬에 따라 **연두** 하이라이트를 남긴다. 대상은 서면에 실제로 인용한 판시 부분이다. **서면 docx 본문에는 형광펜을 칠하지 않는다.**

LBOX 내 AI 기능은 쓰지 않는다. 통합 입력창의 '검색' 모드만 쓴다.

## 5. 서면 작성 규칙

문체·구성·증거 인용·판례 인용·각주 규칙은 전부 `4_서면작성/skills/노동서면작성/` 에 있다. `SKILL.md` 에 문장 규칙·금지 사항·자가 점검이 있고, 문체 용례·표기·증거 인용·판례 인용·구성은 같은 폴더의 `references/` 에 있다. **이 폴더는 `.claude/skills/` 밖에 있어 자동으로 읽히지 않으므로, 초안을 쓰기 전에 `SKILL.md` 와 `references/` 의 모든 파일을 직접 읽는다.** 초안 작성에서는 일부만 읽는 예외를 두지 않는다.

특히 아래 두 가지는 예외가 없다.

- **출력 범위는 "- 다 음 -" 이후부터 입증방법까지이다.** 표지, 사건 정보 표, 날짜·대리인·수신처 블록은 만들지 않는다.
- **출력/서면_프레임.docx 에 목차가 짜여 있으면 그 목차 구조와 항목명을 그대로 따른다.** 프레임에 없는 항목을 임의로 추가하지 않고, 목차에 있는데 내용이 부족하면 `[내용 보완 필요]` 로 표시한다.

## 6. docx 병합

```
python 4_서면작성/scripts/docx_merge.py <출력 폴더>
```

병합 → restyle → 각주 → 원문자 글꼴을 한 번에 처리한다. 끝난 뒤 세 가지를 각각 `--check` 로 확인하고 검출이 0건인지 본다.

| 점검 | 명령 |
|---|---|
| 본문 문단이 제목 계층에 맞는 '내용' 스타일인지 | `python 4_서면작성/scripts/docx_restyle.py <파일> --check` |
| 원문자(①~⑳) 글꼴이 본문과 같은지 | `python 4_서면작성/scripts/docx_normalize.py <파일> --check` |
| 본문에 `[[각주:` 표시가 남지 않았는지 | `python 4_서면작성/scripts/docx_footnotes.py <파일> --check` |
| 금지 낱말·접속부사 쉼표·대괄호 메모·문체 실측치 | `python 4_서면작성/scripts/style_check.py <파일>` |
| 인용한 호증이 목록에 있는지, 판례기록이 있는지 | `python 4_서면작성/scripts/citation_check.py <파일>` |
| 편철한 호증의 1면에 그 호증 도장이 있는지 | `python 4_서면작성/scripts/evidence_check.py stamp <증거폴더>` |
| 편철본의 각 면이 원본 어디에서 왔는지 | `python 4_서면작성/scripts/evidence_check.py trace <원본폴더> <편철폴더>` |
| 표제와 내용이 맞는지 눈으로 볼 이미지 | `python 4_서면작성/scripts/evidence_check.py sheet <편철폴더> --out <경로>` |

병합 후 날짜·대리인 표가 본문 앞으로 밀리지 않았는지 요소 순서를 눈으로 확인한다.

## 7. 반드시 지킬 것

**초안 하단에 세 목록을 붙인다.** ① `[확인 필요 사항]`, ② ⚠️ `[취약 논리 및 보완 방향]`, ③ 📎 `[추가 확보 필요 증거]`.

**본문 안의 대괄호 메모는 docx 에 넣지 않는다.** 하단 목록에만 둔다.

**앞선 라운드의 주장과 모순되는 서술을 하지 않는다.** 입장을 바꿔야 하면 사용자에게 먼저 알린다. 이미 충분히 말한 주장은 되풀이하지 않고 "이 점은 라운드N 서면 OO항에서 말씀드린 바와 같으며" 로 줄인다.

**반박에 자료가 모자라면 지어내지 말고 표시하고 넘어간다.** `[반박 보완 필요]` 아래에 필요한 사실관계, 필요한 증거, 현재 가능한 반박을 적는다.

**서명 블록의 담당변호사는 강 민 석 · 이 수 진 · 김 현 수 이다.** 2026. 9. 10. 부터 적용하며 `4_서면작성/templates/표준양식.docx` 와 `사건/_템플릿` 의 프레임에 이미 반영되어 있다. 이미 제출한 서면과 진행 중 사건의 기존 프레임은 당시 담당이 맞으므로 고치지 않는다. 사건마다 담당이 다르면 사용자에게 확인한다. **법원 서면은 '소송대리인' 표기이므로 노무사를 넣지 않는다. 노동위원회 사건은 '대리인' 표기이고 공인노무사도 대리인이 되므로 담당변호사 강 민 석 · 이 수 진 과 담당노무사 최 락 보 로 적는다**(2-2절). 검토의견서는 서명 블록 형식과 적용 시기가 다르다(`1_검토의견/CLAUDE.md` 6절).

**금액을 직접 계산하지 않는다.** 손해배상액이나 노동 금액(시간외수당·퇴직금·연차수당 차액, 해고기간 임금, 지연손해금)이 청구취지·본문에 들어가면 초안을 쓰기 전에 `.claude/commands/손배계산.md` 절차를 이 사건 폴더로 수행한다(`/손배계산 4_서면작성/사건/{사건명} 라운드N`). 계산 파일은 `라운드N/작업/계산/` 에 두고 본문 숫자는 그 계산표에서만 옮긴다. 상대방 별지 계산을 반박하는 서면은 `/손배검산` 결과를 근거로 쓴다.

**사용자가 시스템 파일을 고치겠다고 하면 현재 내용을 먼저 확인한 뒤 해당 부분만 고친다.** 파일 전체를 새로 쓰지 않는다.
