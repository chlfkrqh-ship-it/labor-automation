# 이메일 회신을 검토의견서(서면)로 전환하는 절차

## 1. 언제 적용하는가

사용자가 "서면으로", "검토의견서로 만들어", "양식에 반영해", "정식 의견서로" 등을 요청할 때 적용한다. 통상 이메일 회신 초안을 먼저 작성한 뒤 후속으로 요청되므로, 내용은 이미 확정된 상태에서 형식만 전환하는 작업이다.

## 2. 필요한 입력 파일

| 파일 | 위치 | 용도 |
|---|---|---|
| 기존 검토의견서 완성본 | `templates/샘플/` | 작업 베이스. 각주·표·서명 블록이 살아 있는 것 |

**작업 베이스는 기존 완성본을 쓴다.** 빈 양식으로 시작하면 각주 인프라와 본문 구조를 처음부터 만들어야 하지만, 완성본은 레터헤드·머리글/바닥글·서명 블록·면책 표·구역 설정이 모두 살아 있어 본문만 갈아끼우면 된다.

## 3. 작업 절차

```
unzip 베이스.docx -d unpacked/
find unpacked -type l -delete
# word/document.xml 본문 교체, word/footnotes.xml 각주 교체
(cd unpacked && zip -Xrq ../out.docx .)
python3 <docx 스킬 경로>/scripts/office/validate.py out.docx --original 베이스.docx
soffice --headless --convert-to pdf out.docx
pdftoppm -jpeg -r 100 out.pdf page   # 전 면 육안 확인 필수
```

`document.xml`은 조각으로 잘라 가운데만 교체한다.

1. `<w:body>` 직후까지 → 그대로 유지
2. 날짜·문서번호·수신·참조·제목 문단 → 새로 생성
3. 짝대기(가로선 도형) 문단 → **원본 XML을 문자열 그대로 복사.** 도형 XML을 재작성하지 말 것
4. 본문(항목 제목 + 본문 문단) → 새로 생성
5. "이상과 같이 법률 의견을 송부하여 드립니다" 문단부터 `</w:body>`까지 → 그대로 유지 (서명 블록, 면책 표, sectPr 포함)
   단, **서명 블록의 담당변호사는 `1_검토의견/CLAUDE.md` 6절의 발송일 기준 표에 따라 고친다.** 베이스가 된 완성본에는 그 사건 당시의 담당이 적혀 있다.

본문 문단의 경계를 정확히 잡으려면 `<w:body>`의 직계 자식을 **태그 깊이 기준으로 스캔**하여 각 자식의 시작·끝 오프셋을 구한 뒤, 유지할 조각은 원본 문자열에서 그대로 잘라 쓴다. 정규식으로 `<w:p ...>...</w:p>`를 비탐욕 매칭하면 `<w:pPr>` 등에 걸려 어긋난다.

## 4. 스타일 ID 매핑

**스타일 ID는 파일마다 다르다.** 반드시 해당 파일의 `word/styles.xml`을 파싱해 `w:name` 기준으로 `w:styleId`를 조회한 뒤 사용한다. 이름만 보고 ID를 추측하지 말 것.

예: HPS·OES 파일 기준 매핑은 아래와 같으나, 빈 양식 파일은 ID 체계가 다르다.

| 스타일 이름 | styleId | 용도 |
|---|---|---|
| 날짜 및 문서번호 | `aff0` | 우측 상단 문서번호·날짜 |
| 수신 참조 제목 | `aff1` | 수신/참조/제목 (라벨과 값 사이 `<w:tab/>`) |
| 짝대기 | `aff2` | 제목 아래 가로선 |
| 1. | `1` | 항목 제목, 자동번호 |
| 본-문 | `-` | 본문 |
| 각주 | `aff3` | 각주 문단 |
| footnote reference | `af6` | 각주 번호 문자 스타일 |

`1.`의 styleId는 `1`이지 `1.`이 아니다. `w:val="1."`로 쓰면 LibreOffice에서는 정상으로 보이지만 Word에서 스타일이 풀린다. 생성 후 python-docx로 다시 읽어 항목 제목의 `style.name`이 `'1.'`로 나오는지 확인한다.

문단 XML 형식:

```xml
<!-- 항목 제목 (첫 항목만 spacing 추가) -->
<w:p><w:pPr><w:pStyle w:val="1"/><w:spacing w:before="240"/></w:pPr>
  <w:r><w:rPr><w:rFonts w:hint="eastAsia"/></w:rPr><w:t xml:space="preserve">...</w:t></w:r></w:p>

<!-- 본문 -->
<w:p><w:pPr><w:pStyle w:val="-"/></w:pPr>...</w:p>

<!-- 항목 사이 빈 줄 -->
<w:p><w:pPr><w:pStyle w:val="-"/></w:pPr></w:p>
```

## 5. 각주 처리

인용은 본문 괄호가 아니라 **각주**로 단다. 괄호 형식은 이메일 회신에 적용하고, 검토의견서에서는 각주 형식을 쓴다.

본문 참조 run:

```xml
<w:r><w:rPr><w:rStyle w:val="af6"/></w:rPr><w:footnoteReference w:id="2"/></w:r>
```

`word/footnotes.xml`의 구분선 각주는 건드리지 말고 내용 각주만 교체한다. 구분선의 `w:id`는 파일마다 다르므로(`0`,`1`인 파일도 있고 `-1`,`0`,`1`인 파일도 있다) 직접 확인한 뒤 그 다음 번호부터 쓴다.

```xml
<w:footnote w:id="2"><w:p><w:pPr><w:pStyle w:val="aff3"/></w:pPr>
  <w:r><w:rPr><w:rStyle w:val="af6"/></w:rPr><w:footnoteRef/></w:r>
  <w:r><w:t xml:space="preserve"> </w:t></w:r>
  <w:r><w:rPr><w:rFonts w:hint="eastAsia"/></w:rPr><w:t xml:space="preserve">대법원 2026. 5. 2. 선고 2025다1234 판결.</w:t></w:r>
</w:p></w:footnote>
```

각주 대상은 판례, 행정해석, 계약 조항이다. **법령 조문은 각주로 빼지 말고 본문에 "(같은 법 제35조)" 형태로 인라인 처리한다.** 각주 문장 끝에는 마침표를 찍고, 확정 여부는 괄호로 붙인다.

## 6. 본문 작성 규칙

- **첫 항목은 `결론 요지`로 세운다.** 이메일과 서면의 차이는 분량이지 구조가 아니다.
- 항목 제목은 쟁점을 질문형으로 세운다. "~하는지 여부", "~하는 경우". 자동번호가 붙으므로 제목에 번호를 직접 쓰지 않는다.
- 상대방은 "귀사"로 지칭한다.
- 항목당 본문은 3~5문단. 이메일 회신본의 표·불릿은 문단으로 풀어 쓴다.
- **문체는 `문체가이드-서면.md`에 따른다. 본문을 쓰기 전에 그 문서를 읽는다.**

## 7. 금지사항

- 새 표를 삽입하지 않는다. 양식에는 하단 면책 문구용 표만 정의되어 있어 본문용 표 스타일이 없다. 표가 꼭 필요하면 별도 첨부 파일로 뺀다.
- 짝대기 도형, 서명 블록, 면책 표, 머리글/바닥글, `sectPr`을 재작성하지 않는다. 원본 XML을 그대로 옮긴다.
- `document.xml`을 pretty-print 하거나 재포맷하지 않는다.
- 문서번호는 임의로 채우지 않는다. `2026-L-000`으로 두고 사용자에게 채번을 요청한다. 날짜는 작성일로 채운다.
- 참조란의 부서명·담당자명을 추측하여 채우지 않는다. 확인되지 않으면 사용자에게 묻는다.

## 8. 파일명

`({의뢰인 약칭}) {사안} 관련 검토.docx` 형식으로 한다. **의뢰인 약칭은 괄호로 감싼다.** 예: `(HPS) 월성 수주 이후 단체교섭 등 관련 검토.docx`
