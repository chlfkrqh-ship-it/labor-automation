# 노임표·생명표 추출 절차

`data/` 의 CSV 4종을 만드는 작업이다. **한 PC에서 한 번만 하면 된다.** 산출물은 감사 컬럼이 제거된 공공통계 수치이므로 OneDrive로 동기화되어 다른 PC에서도 그대로 쓰인다.

| 산출 파일 | 내용 | 원본 테이블 |
|---|---|---|
| `data/life_table.csv` | 생명표 (1991~2024, 연령 0~100) | TB_SUT002 |
| `data/wage_quarterly.csv` | 분기별 노임단가 (농촌 남/여, 도시일용) | TB_SUT001 |
| `data/occupation.csv` | 직종 마스터 | TB_SUT003 |
| `data/wage_occupation.csv` | 직종별 반기 노임단가 | TB_SUT004 |

## 한 번에 하는 방법

`노임표추출.bat` 을 **더블클릭**한다.

검은 창이 뜨고 진행 상황이 찍히며, 끝나도 창이 닫히지 않는다. 창이 아예 뜨지 않으면
파일이 차단된 것이므로 우클릭 → 속성 → 하단 **[차단 해제]** 를 체크한다.

프로그램 설치 위치를 스스로 찾고, 스냅샷을 뜨고, **32비트 PowerShell로 알아서 갈아탄 뒤**
덤프·정규화·확인까지 한다. 설치 위치를 못 찾으면 직접 알려 준다.

```powershell
.\노임표추출.ps1 -SutPath "D:\내가\깐\경로"
```

아래는 이 스크립트가 하는 일을 단계별로 풀어 둔 것이다. 자동 실행이 중간에 막혔을 때 본다.

## 전제

1. **대법원 「손해배상 등 계산프로그램」이 `C:\work\sut` 에 설치되어 있어야 한다.** `tools/` 의 세 스크립트가 이 경로를 그대로 적어 두고 있으므로, 다른 곳에 깔려 있으면 스크립트의 경로를 먼저 고친다. 설치 위치는 바로가기 속성의 [대상]에서 확인한다.
2. **32비트 ACE OLEDB 공급자가 필요하다.** SUT 본체가 x86이므로 함께 깔려 있을 가능성이 높다. 없으면 Microsoft Access Database Engine 2016 **x86** 을 설치한다. 64비트 Office가 깔린 PC에서는 설치가 거부되므로 `AccessDatabaseEngine_X86.exe /quiet` 로 우회한다.

## 1단계 — 프로그램 폴더 스냅샷

`SUT.Updater.exe` 가 자동 갱신하며 덮어쓰므로 먼저 박제한다. 나중에 계산이 달라졌을 때 어느 버전과 대조한 것인지 알 수 있어야 한다.

```powershell
cd <저장소>\6_손해배상계산
powershell -ExecutionPolicy Bypass -File tools\01_snapshot.ps1
```

`C:\sut_snapshot\{버전}` 에 복사된다. `Logs\` 는 제외된다(log4net이 DEBUG 레벨이라 사건 데이터가 남아 있을 수 있다).

## 2단계 — accdb를 CSV로 덤프

**반드시 32비트 PowerShell로 실행한다.**

```
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe
```

를 띄운 뒤,

```powershell
cd <저장소>\6_손해배상계산
Set-ExecutionPolicy -Scope Process Bypass -Force
.\tools\02_dump_accdb.ps1
```

`C:\sut_extract\db\{Common,CortCalc,DamgCalc}\*.csv` 가 만들어지고, 테이블별 행 수가 화면에 찍힌다. **TB_SUT001~004 네 개가 어느 폴더에 있는지 확인한다.** 통상 `CortCalc` 이다.

## 3단계 — 정규화

```powershell
cd <저장소>\6_손해배상계산
python scripts\normalize.py C:\sut_extract\db\CortCalc
```

2단계에서 네 테이블이 다른 폴더에 있었으면 인자를 그 폴더로 바꾼다. 담당자 ID·프로그램 ID·변경일시 컬럼은 이 단계에서 제거된다.

## 4단계 — 확인

```powershell
python -m pytest tests\ -q
python -c "from engine.tables import LifeTable, WageTable; lt=LifeTable.load(); print('생명표 연도', min(lt.years), '~', max(lt.years)); print('60세 남 기대여명', lt.expectancy(2024, 60, 'M'))"
```

테스트 62건이 통과하고 기대여명이 상식적인 값(60세 남자 기준 20년대 초반)으로 나오면 된다.

## 실패했을 때

| 증상 | 원인 |
|---|---|
| `Microsoft.ACE.OLEDB.12.0 공급자는 로컬 컴퓨터에 등록할 수 없습니다` | 64비트 PowerShell로 실행함. `SysWOW64` 경로로 다시 띄운다 |
| `32비트 PowerShell 로 실행하세요` | 스크립트 자체의 가드. 같은 원인 |
| 스크립트가 실행되지 않음 | 실행 정책. `-ExecutionPolicy Bypass` 또는 `Set-ExecutionPolicy -Scope Process Bypass` |
| `sut_version.ini` 를 못 찾음 | 설치 경로가 `C:\work\sut` 가 아님. 세 스크립트의 경로를 고친다 |
| `TB_SUT002.csv` 가 없다는 오류 | 2단계에서 네 테이블이 나온 폴더를 3단계 인자로 주지 않았다 |
| ACE 설치가 거부됨 | 64비트 Office 충돌. `/quiet` 스위치로 설치한다 |

## 하지 않는 것

`tools/03_decompile.ps1` 은 계산 로직 어셈블리를 C# 소스로 복원하는 것으로, 엔진을 처음 만들 때 쓴 것이다. 노임표 추출에는 필요하지 않으니 지금은 건너뛴다. 나중에 프로그램이 갱신되어 계산이 달라졌을 때, 스냅샷과 대조하려면 그때 쓴다.

## 저장소에 넣지 않는 것

`C:\sut_extract`, `C:\sut_snapshot` 은 저장소 밖에 둔다. 프로그램 원본과 감사 컬럼이 그대로 들어 있다. 저장소에 들어가는 것은 `data/` 의 정규화된 CSV 4종뿐이다.
