# 6_손해배상계산

대법원 「손해배상 등 계산프로그램」(신 손해배상)의 계산을 로컬에서 재현하고,
손해배상액 계산표 엑셀을 만든다. 노동사건 금액(수당·퇴직금·연차수당 차액, 해고기간 임금, 지연손해금)은
`engine/labor/` 가 계산한다(아래 '노동 금액' 절).

아래 '절대 규칙'은 두 엔진 모두에 적용한다. ③의 대법원 프로그램 크로스체크는 신체손해에만 해당하고,
노동 금액은 담당자 검산으로 대신한다.

## 절대 규칙

### ① 금액을 직접 계산하지 않는다
호프만 계수, 중복장해율, 기간분할, 과실상계, 공제는 **전부 `engine/` 이 한다.**
암산이나 어림으로 숫자를 내지 말 것. 끝수처리가 항목마다 다르고(누적합은 절사,
적용호프만 차이는 반올림, 금액은 원 미만 절사) 손으로 하면 반드시 틀린다.

계산이 필요하면 `python cli.py` 또는 `python watch.py` 를 돌리고 그 출력을 쓴다.

### ② 프로그램 원본과 추출물은 이 폴더 밖에 둔다
`C:\sut_extract`, `C:\sut_snapshot` 은 이 폴더로 들여오지 않는다. 대법원 프로그램 원본과
담당자 ID·프로그램 ID 같은 감사 컬럼이 그대로 들어 있다. 들어오는 것은 `data/` 의
정규화된 CSV 4종뿐이다.

사건 자료(`사건/`, `01_입력/`, `02_결과/`, `03_보관/`, `99_오류/`)는 OneDrive로 동기화된다.
백업 zip과 `.gitignore` 에서는 제외되어 있다.

### ③ 제출본은 대법원 프로그램으로 크로스체크한다
엔진은 골든 케이스 3건과 판례 계수 10건으로 검증됐지만, 아직 밟지 않은 분기가 있다
(여명단축, 한시장해, 조정 사건의 지연이자, 상속지분, 개호비 실사용).
초안·검토용으로 쓰고 **법원 제출본은 프로그램에서 다시 확인한다.**

## 두 가지 입력 방식

### (a) 엑셀 입력서 — 결정론적, 자료가 밖으로 나가지 않는다
`00_양식/입력서.xlsx` 를 복사해 노란 칸을 채우고 `01_입력/` 에 넣는다.
`watch.py` 가 읽어 `02_결과/` 에 계산표를 낸다. 사람이 값을 적으므로 오류가 없다.

    python watch.py --loop

### (b) 자료 폴더에서 읽어 계산 — 초안 작성용
`사건/<사건명>/` 에 진단서·판결문·급여명세서 등을 넣고, 저장소 루트에서 `/손배계산 <사건명>` 을 부른다.
AI가 자료를 읽어 `사건.yaml` **초안**을 만들고, 사람이 확인한 뒤 엔진이 계산한다.

**AI가 읽는 것은 항목 추출까지다. 계산은 반드시 엔진이 한다.**
추출한 값은 근거 파일과 쪽수를 함께 적어 사람이 대조할 수 있게 한다.

## 검증 상태

| 항목 | 근거 |
|---|---|
| 호프만·라이프니츠, 240 상한, 끝수처리 | 프로그램 소스 + 골든 3건 + 판례 계수 10건 |
| 중복장해율, 기왕증 기여도 | 소스 + 골든 |
| 노임 기간분할(5/1·9/1 경계) | 소스 + 골든 |
| 일실수입 순번, 안분액 | 소스 + 골든 |
| 치료비·보조구 수치합계(상한 240÷수명) | 소스 + 골든 |
| 초일산입, 연령 계산 분리 | 소스 + 골든 |
| 과실상계·공제·위자료 | 골든 역산 |
| 개호비 | 소스 (프로그램 출력 대조 미완) |

## 자주 틀리는 지점

- **반기 경계는 달력 반기가 아니다.** 전년 9.1.~당해 4.30.이 상반기분,
  당해 5.1.~8.31.이 하반기분이다.
- **240 상한은 청구기간 기준이다.** `min(H(총기간) − H(제외기간), 240)`.
  대법원 2022. 6. 16. 선고 2022다211393 판결. `240 − H(제외)` 는 구방식이다.
- **치료비·보조구 상한은 20이 아니라 `240 ÷ 수명(월)`** 이다. 설명서의 20은
  수명이 12개월일 때의 값일 뿐이다.
- **연령은 초일산입이 없다.** 기간 계산(`diff_ymd`)과 연령(`age_at`)은 다른 함수다.
- **가동연한 기본값은 65년**, 가동종료일은 생년월일 + 가동연한 − 1일.
- **월 가동일수는 직종별 20일, 농촌 25일** (대법원 2020다271650).

## 노임표·생명표

`data/` 의 CSV 4종을 쓴다. 없으면 사용자에게 `노임표추출.bat` 더블클릭을 안내한다
(설치 위치 탐색·스냅샷·32비트 전환·덤프·정규화·확인까지 한 번에 한다).
막히면 `노임표-추출-절차.md` 의 단계별 설명과 실패 표를 본다. 입력서의
`[노임단가 직접입력]` 표에 값을 적으면 그것이 우선하므로, 표가 없어도 그 사건은 계산할 수 있다.

**추출은 사용자가 직접 한다.** PowerShell 32비트 실행과 대법원 프로그램 설치 경로가
걸려 있어 자동화하지 않는다. 실패 사유를 물으면 `노임표-추출-절차.md` 의 표를 본다.

## 노동 금액 (engine/labor/)

통상시급, 연장·야간·휴일수당 차액, 미사용 연차휴가수당, 평균임금·법정 퇴직금 차액, 해고기간 임금 상당액과
중간수입 공제, 지연손해금·소멸시효 만료일을 계산한다. 신체손해 엔진과 입력·출력이 분리되어 있다.

- **입력은 사건.yaml(`kind: labor`) 하나다.** 형식은 `cases/labor_sample.yaml`(퇴직 근로자 재산정),
  `cases/labor_dismissal_sample.yaml`(부당해고), 절마다 키 설명은 각 모듈 머리 docstring.
  엑셀 입력서는 아직 없다. `01_입력/` 에 yaml 을 넣으면 `watch.py` 도 처리한다.
- **규칙·옵션·상태는 `노동금액-계산기준.md`** 에 있다(코드에서 생성 — `python scripts/노동기준표.py`).
  모듈 `RULES`·`OPTIONS` 를 고치면 이 스크립트를 다시 돌린다.
- **법적 판단은 입력이다.** 통상임금 해당 여부(2024. 12. 18.까지 구 법리 / 19.부터 새 법리 두 칸), 해고기간 임금 항목,
  중간수입 휴업수당 기초 방식(`ii_cap_base`), 초과 지급분 충당(`ot_overpayment_character`) 등은 사람이 정한다.
  기본값이 없는 옵션은 결과가 달라질 때 엔진이 멈추고 선택을 요구한다. 추측해서 채우지 않는다.
- **계산표 '근거' 시트의 노란 행(불명확 규칙)** 과 '요약' 시트의 대안 결과(개정법 미적용·청구 최대)는 서면·검토의견에 옮길 때
  함께 본다. '경고' 시트는 전부 사용자에게 전한다.
- 대법원 계산프로그램이 없는 영역이다. 판결 숫자로 검증한 범위는 `tests/test_labor_*.py`, 법원 제출 전 담당자가 검산한다.

### 자주 틀리는 지점

- **2024. 12. 19.** 통상임금 새 법리(고정성 폐기)는 이날 이후 제공한 근로분부터. 걸친 달은 `from/to` 로 나눈다. 병행사건 항목은 소급.
- **월 기준시간** 209는 반올림 결과다. 208.57·226·243 과 옵션으로 구분(`ow_month_hours_rounding`, 약정 유급처리시간).
- **연장근로** 1일 8시간 초과와 1주 40시간 초과를 겹쳐 세지 않는다. 2018. 3. 20. 전 휴일근로는 주 40시간에 넣지 않는다.
- **평균임금 산정기간**은 산정사유 발생일(퇴직금이면 마지막 근무일 다음 날)을 빼고 3개월. 상여·연차수당은 3/12.
- **중간수입 공제**는 월별 `min(중간수입, 임금 − 휴업수당)`. '중간수입 − 휴업수당' 공제와 '수입이 휴업수당보다 적으면 공제 0' 은 위법 산식이라 입력 단계에서 거부한다.
- **지연손해금 20%** 는 퇴직 청산 금품이면 마지막 근무일 + 15일부터. 구법 도래분 해고기간 임금은 복직이면 20% 없음(2014다28305). 사용자 주장에 상당한 근거가 있으면 사실심 선고일까지 배제.
- **지연손해금 일할**은 만 N년 + 잔여일/365(잔여기간에 2. 29. 있으면 366), 구간별 원 미만 버림.

## 테스트

    python -m pytest tests/ -q

`tests/test_golden.py` 가 프로그램의 실제 엑셀표저장 결과와 대조한다.
엔진을 고쳤으면 반드시 통과시킨 뒤 결과를 보고하고, 통과한 것을 올린다(`공통/운영.md` '시스템 파일 올리기'). 엔진 소스는 git으로 관리된다.
