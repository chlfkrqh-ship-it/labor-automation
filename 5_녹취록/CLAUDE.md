# 5_녹취록

녹음파일을 녹취서 형식(화자·타임스탬프 표기)으로 전사한다.

**작업은 두 단계로 나뉜다.** 스크립트가 전사와 화자 *구간* 분리까지 하고, 명령어가 그 결과를 읽어 화자에 *이름*을 붙이고 녹취서를 만든다. 이 둘을 섞지 않는다.

| 단계 | 하는 일 | 누가 | 산출물 |
|---|---|---|---|
| 1 전사 | 음성 → 텍스트, 목소리 기준 화자 구간 분리 | `transcribe.py` | `.녹취.txt` `.녹취.json` |
| 2 배정 | 화자 구간에 이름 붙이기, 녹취서 작성 | `/녹취` 명령어 | `녹취서_*.md` 또는 `녹취록_*.md` |

## 1. 준비

이 폴더는 다른 다섯과 달리 **PC마다 환경 설치가 필요하다.** 처음 쓰는 PC에서는 `녹취록 환경설치.bat` 을 한 번 더블클릭한다. 설치 절차·검증 결과 읽는 법·자주 겪는 문제는 `설치안내-녹취.md` 에 있다.

**전사와 화자 분리 모두 CPU로 한다. GPU도 HuggingFace 토큰도 필요 없다.**

- 전사는 faster-whisper. 보유 PC 두 대(회사 GTX 750 Ti, 집 GTX 1050)는 Maxwell·Pascal 세대여서 PyTorch CUDA 빌드에서 아키텍처 지원이 빠졌고 VRAM도 부족하다.
- 화자 분리는 sherpa-onnx(ONNX Runtime). CPU에서 돈다. 47초 통화를 10.5초에 처리했다(실측, 약 4.5배속). 모델은 세그멘테이션 + 화자임베딩 두 개로 합계 35MB이며 `models/` 에 들어 있다.

**기본 모델은 `large-v3-turbo` 다.** 3분 55초짜리 한국어 음성으로 실측한 결과 large-v3는 527초, turbo는 192초가 걸렸고, large-v3 쪽에서만 같은 문장을 여러 번 되풀이하는 반복 환각이 세 군데 나왔다. turbo가 더 빠르면서 오탈자도 적었다.

**가상환경은 이 폴더가 아니라 `%LOCALAPPDATA%\노동사건자동화\` 에 있다.** OneDrive가 동기화하지 않는 자리이며, 용량이 수 GB이고 PC마다 따로 받아야 하므로 공유해서는 안 된다. 이 폴더 안에 `.venv`를 만들지 않는다. 화자 분리 모델 35MB는 예외로 `models/` 에 함께 둔다.

## 2. 폴더 배치

```
5_녹취록/사건/{사건폴더}/
├─ 원본/                  ← 음성파일을 여기에 넣는다 (m4a, mp3, wav, mp4 등)
├─ 전사/                  ← 1단계 산출물
│  ├─ {이름}.녹취.txt        사람이 읽는 전사본 + 확인 필요 구간
│  ├─ {이름}.녹취.json       구간·타임스탬프·신뢰도·화자턴 (2단계 입력)
│  └─ {이름}.부분.jsonl      중단 대비 기록. 정상 종료하면 지워진다
└─ 녹취서_{이름}.md       ← 2단계 산출물 (간이 모드는 녹취록_{이름}.md)
```

경로를 주어 돌린 간이 모드는 원본과 같은 폴더에 `.녹취.txt`·`.녹취.json` 이 생기고, `녹취록_{이름}.md` 도 그 폴더에 둔다.

## 3. 실행

가상환경을 활성화하지 않고, 저장소 루트에서 실행 정책을 우회해 래퍼를 부른다.

```
powershell -NoProfile -ExecutionPolicy Bypass -File 5_녹취록/녹취.ps1 {사건폴더명} -Speakers 2
```

- `.\녹취.ps1` 로 바로 부르지 않는다. 실행 정책이 Restricted 인 PC에서는 막히고, bash 에서는 `\` 가 사라진다. 경로 구분자는 `/` 를 쓴다.
- 사건 폴더명을 주면 `사건/{이름}/원본/` 의 음성파일을 모두 처리해 `전사/` 에 넣는다.
- 파일이나 폴더 경로를 직접 주면 간이 모드로 그 자리에 결과를 남긴다. 래퍼가 이 폴더로 옮겨 가서 경로를 읽으므로 절대경로로 준다.
- **간이 모드 대상이 저장소 안이면 `사건/` 아래에 있어야 한다.** 저장소 안이면서 `사건/` 밖(예: `5_녹취록/` 바로 아래)에 있는 녹음을 그대로 돌리면 전사본이 시스템 파일 자리에 남아 git 으로 올라갈 수 있다. 먼저 `사건/{이름}/원본/` 으로 옮기고 사건 폴더명으로 돌린다.
- **`-Speakers` 로 화자 수를 지정한다.** 통화는 2, 3자 면담은 3. 지정하면 정확해진다.
- `-NoDiarize` 로 화자 분리를 끈다. `-Model large-v3` 처럼 모델을 바꿀 수 있다.
- 전사 시간은 녹음 길이와 비슷하다. 한 시간짜리면 한 시간가량 잡아 둔다. 화자 분리는 그 위에 녹음 길이의 4분의 1가량이 더 붙는다.

**화자 수를 지정하지 않으면 과분할한다.** 2인 통화를 자동 판단에 맡겼더니 화자를 6명으로 나눴다(임계값 0.5). 기본 임계값을 0.8로 올려 두었으나 지정하는 편이 확실하다.

**중단에 대비한다.** 세그먼트가 나올 때마다 `.녹취.txt` 와 `.부분.jsonl` 에 즉시 기록한다. 두 시간짜리 작업이 중간에 끊겨도 그때까지 결과는 남는다.

## 4. 화자 배정은 추정이다

**이것이 이 폴더에서 가장 중요한 규칙이다.**

1단계가 나눈 것은 **목소리 구간**이다. `화자1`·`화자2` 는 "서로 다른 사람"이라는 뜻일 뿐, 누가 누구인지는 담고 있지 않다. 그 구간이 누구인지 정하는 일은 2단계에서 대화 맥락 — 존대 관계, 질문·응답 구조, 호칭, 지위가 드러나는 발언 — 으로 한다. **이것은 추정이다.**

- **정식 모드에서도 녹취서 말미에 `화자 배정은 대화 맥락에 따른 것으로 청취 검수를 거치지 않았음` 을 반드시 적는다.**
- **사용자가 검수를 마쳤다고 확인한 뒤에만 그 문구를 뺀다.** 사용자가 말하지 않았는데 먼저 빼지 않는다.
- 배정 근거가 약한 구간은 `화자?` 로 남기고 마무리 보고에 목록으로 올린다.
- 말이 겹치는 구간에서는 음향 분리도 틀린다. 한 발화 블록에 명백히 다른 사람의 말이 섞여 있으면 그 부분만 맥락으로 가른다.

## 5. 확인 필요 구간

전사기가 스스로 자신 없어 한 구간을 뽑아 둔다. 판정 기준은 세그먼트의 `avg_logprob < -1.0` 또는 `no_speech_prob > 0.5` 이다.

- `.녹취.txt` 파일 끝에 타임스탬프와 사유가 목록으로 실린다. 본문 해당 줄 끝에도 `※확인` 이 붙는다(화자 분리 판은 확인 필요 구간과 겹치는 발화 줄에 붙고, `.녹취.json` 의 `turns` 에 `review: true` 로 남는다). 빠뜨리지 않으려면 파일 끝 목록과 `review_needed` 를 기준으로 본다.
- `.녹취.json` 의 `review_needed` 에 같은 내용이 들어 있다.
- 이 목록을 마무리 보고에 그대로 올린다. **사용자는 이 지점만 들어보면 된다.**

## 6. 결과를 다룰 때

**전사 결과를 임의로 고쳐 쓰지 않는다.** 자동 전사이므로 오탈자가 남아 있는 것이 정상이고, 무엇이 실제 발언인지는 사용자가 원본을 들어 판단할 몫이다.

- 맞춤법 교정은 **고유명사와 노동관계 용어의 명백한 오인식에만** 적용한다. 구어체·비문·말 반복·말끝 흐림은 그대로 둔다.
- 사건과 무관한 사적 대화라도 **임의로 생략하지 않는다.**
- 사용자가 교정을 요청한 경우에만 수정하고, **무엇을 고쳤는지 밝힌다.**
- 요약·쟁점 정리를 요청받으면 전사본과 녹취서는 그대로 두고 별도 파일로 만든다.
- 증거로 제출할 녹취서라면 사용자의 청취 검수가 반드시 선행되어야 한다는 점을 알린다. 잡음 없는 합성 음성에서도 문자 오류율이 1%대였고, 실제 면담 녹음은 겹말·잡음·사투리가 섞여 이보다 나쁘다.

녹취서 형식과 표기 규칙은 `녹취서-작성-가이드.md` 에 있다.
