# 공통화 구현·검증 기록

기준일: 2026. 9. 10.

## 반영 범위

1. GPT 연결: 업무 폴더 6개의 AGENTS 안내, labor-workflow 스킬, 기존 슬래시 요청의 공통 경로 연결.
2. 범용 운영: 루트 공통 규칙, 공통 명령어 13개, 공통 스킬 3개, 생성본 26개 동기화와 직접 수정 충돌 감지. 기존 업무 규칙과 엔진은 재사용.
3. 효율: 파일 해시 기반 변경 목록, 검토 완료와 구별되는 기준 목록, PDF·DOCX·텍스트 추출 캐시, 범위별 출력, 조건부 문체 참조, 공통 DOCX 변환 지침.
4. 결과 비교: 동일 과제·입력·규칙 복사 고정, GPT·Claude별 독립 요청, 결과 원본 보존, 모델·실측 사용량 기록, 문자·판례번호·호증 대조, 원문 기반 평가 절차.

Astra·Sol 역할 분담, 자동 모델/API 호출, 사용자 계정 설정 변경은 포함하지 않았다.

## 완료한 검사

- unittest 11건 통과: 루트 밖 경로 거부, 동기화 반복 실행, 사용자 직접 수정 보호, 원본 지침 변경 전파, 자료 변경·삭제 감지, 캐시 재사용·무효화, DOCX 각주 추출, 고정 입력·과제 변경 감지, 가상 결과 비교와 원본 변경 감지, 미지원 원자료 목록 보존.
- `system.py check`: 생성본 26개 일치, 필수 명령어 누락 0, 스킬 필수 메타데이터 오류 0.
- `공통/시스템.ps1 check`: 현재 PC의 번들 Python을 찾아 실행 성공.
- 기존 박준선 사건 PDF·DOCX에서 텍스트 추출 성공, PDF 두 번째 호출의 캐시 재사용 확인. 추출 캐시 2개만 해당 사건 작업 폴더에 추가.
- 박준선 사건 파일 162개 목록화. 기준 목록 저장(`--accept`)은 실행하지 않았고, 미검토 원자료를 검토 완료로 처리하지 않음.

번들 스킬 검증기의 PyYAML 의존성이 없어 해당 검증기는 실행하지 못했다. 대신 공통 검사에서 실제 사용한 단순 frontmatter의 필수 필드·폴더명 일치를 검사했다. 전체 YAML 스키마 검증을 완료했다고 보지는 않는다.

## 실제 업무에서 남은 검증

- GPT·Claude 두 제품으로 같은 사건 서면을 독립 작성하고 담당자 수정 부담·누락·실제 사용량을 비교하는 실험.
- 각 PC와 제품의 LBOX 로그인·검색·하이라이트 저장 확인. 내부 API·화면 조작의 동등성을 아직 실사용 검증하지 않음.
- 새로 작성하는 제출용 DOCX의 전체 렌더·시각 확인. 이번에는 기존 서면 내용을 수정하거나 재생성하지 않음.

문자 대조 결과는 법적 우열 판정이 아니다. 실제 비교 요청은 `공통/결과비교.md`에 따라 원문 검토를 포함하여 처리한다. 절감률은 실측 전 미확인이다.
