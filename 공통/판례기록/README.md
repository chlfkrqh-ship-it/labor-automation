# 판례 기록

사건을 넘나들며 재사용하는 판례 메모를 모은다. 파일 하나에 판례 하나이고, 이름은 `{법원}_{사건번호}.md` 이다(예: `대법원_2010두20362.md`). 법원명은 LBOX URL과 같게 공백 없이 붙여 쓴다.

작성 형식과 사용 규칙은 `.claude/skills/lbox-검색/SKILL.md` 의 '7. 검색 기록과 판례 기록'에 있다.

**이 폴더는 탐색용이고 인용의 최종 검증을 대체하지 않는다.** 여기 적힌 문장이라도 서면·검토의견에 인용할 때에는 LBOX 원문에서 다시 확인하고, 그 자리에서 이번 작업 색으로 하이라이트를 새로 칠한다. 기록만 보고 인용하면 하이라이트가 남지 않아 사용자가 이번 작업에서 그 판례를 썼는지 확인할 수 없게 된다. 기록이 있다고 해서 검색 범위를 줄이지 않는다.

`공통/캐시/` 와 달리 재생성되지 않는 자료이므로 시스템 백업에 포함된다. 사건별 검색 이력은 각 사건의 `작업/검색기록.md` 에 남기고 여기에 두지 않는다.

## 적지 않는 것

**이 폴더는 시스템 파일이어서 git 으로 GitHub 원격에 올라간다.** 사건 폴더처럼 `.gitignore` 로 빠지지 않으므로, 우리 사건에서 온 개인정보와 의뢰인 내부 사정은 어느 칸에도 적지 않는다.

- '확인한 날짜와 확인한 사건' 줄에는 확인한 날짜와 사건을 알아볼 짧은 이름만 적는다. 예: `2026. 9. 17. 업무상질병 판정 준비`. 사건 폴더 이름에 사람 이름이 들어 있으면 그 이름은 빼고 쟁점으로 적는다.
- 우리 사건의 사람 이름(의뢰인·상대방·제3자 근로자), 소속(지사·부서 등), 병명·진단명 같은 건강 정보, 범죄 혐의를 적지 않는다. 판결문에 나오는 당사자 표시(원고 3 등)와 판시는 원문 그대로 옮긴다.
- '사안 전제'를 비롯한 다른 칸에도 의뢰인·상대방의 내부 규정(취업규칙·징계규정 조문의 내용 등)과 우리 서면에서 어떻게 썼는지 같은 서면 전략을 적지 않는다. 그런 내용은 그 사건의 `작업/검색기록.md` 에, 사건 폴더가 없는 작업은 `공통/캐시/판례검색기록/` 의 기록에 적는다.
- 이 규칙을 두기 전에 적힌 줄은 사용자가 정리 방법을 정할 때까지 그대로 둔다.
