# 브라우저 연결

공통 LBOX 스킬(`lbox-검색`, `lbox-하이라이트`)이 검색 범위·원문 확인·색상 규칙의 원본이다. 이 문서는 **그 일을 어느 브라우저로 하는지**만 정한다.

## 인앱 브라우저를 먼저 보고, 로그인되어 있지 않으면 외부 엣지 브라우저를 쓴다

LBOX는 한 계정에 동시에 3곳까지만 로그인된다. 회사 PC와 집 PC에서 인앱 브라우저와 외부 브라우저를 모두 쓰면 4곳이어서 한 곳은 로그아웃될 수밖에 없다. 그래서 인앱 브라우저로만 한다는 종전 원칙(2026. 9. 16.)은 2026. 9. 17. 폐기했다.

1. **인앱 브라우저(Claude 데스크톱 앱의 브라우저 패널)에서 LBOX 로그인 상태를 먼저 확인한다.** lbox.kr 탭에서 `GET /gw/research/api/v3/precedents/대법원-2002두6866/highlights` 가 200이면 로그인, 401이면 로그아웃이다.
2. 로그인되어 있으면 인앱 브라우저로 한다.
3. **로그인되어 있지 않으면 인앱에 로그인해 달라고 하지 않고 외부 엣지 브라우저로 옮긴다.** 인앱에 다시 로그인하면 다른 PC나 다른 브라우저의 로그인이 끊긴다. Claude에서는 엣지에 설치된 Claude in Chrome 확장으로 조작한다.
4. 엣지도 로그인되어 있지 않으면 사용자에게 알린다. **로그인은 사용자가 직접 한다.** 아이디·비밀번호를 대신 입력하지 않는다.
5. **로그아웃 상태로는 검색·본문 수신을 하지 않는다.** 로그인 여부에 따라 받는 결과가 달라질 수 있다(2026. 9. 16. 사용자 지적).
6. 한 작업의 검색·정독·하이라이트는 되도록 한 브라우저에서 끝낸다. 도중에 로그인이 풀려 옮기면 옮긴 단계와 이유를 검색기록에 적는다. 하이라이트는 계정에 저장되므로 어느 브라우저에서 칠해도 같은 판례에 남는다(2026. 9. 17. 인앱에서 칠한 하이라이트가 엣지에서 그대로 조회됨).
7. 검색기록에 어느 브라우저(인앱/엣지)를 썼는지 적는다.


## 인앱 브라우저에서 확인된 것 (2026. 9. 16.)

| 단계 | 상태 |
|---|---|
| 검색 API `POST /gw/research/api/v1/search` | 됨. 외부 크롬과 결과가 같다(`"직장 내 괴롭힘" "업무상 적정범위"` 728건, 대법원 필터 6건) |
| 판례 본문 수신(`lboxText`) | 됨 |
| 스크립트 붙여 넣기 | `async function`·`const` 선언은 다음 실행에 남지 않고 일반 `function`만 남는다(2026. 9. 17. KEPS 세션 실측). `lbox-검색` 코드 블록 끝의 `Object.assign(globalThis, …)`로 전역에 올린다 |
| 세션 간 저장소 공유 | 됨. 한 세션이 `localStorage`에 남긴 `lbox경고`를 다른 세션의 `lboxUsage()`가 읽었다(2026. 9. 17.). 요청 차례(Web Locks)가 세션 사이에 공유되는지는 두 세션을 동시에 돌려 확인하지 않았다 |
| 유권해석 원문 열기 `https://lbox.kr/interpretation/{documentId}` | 됨(2026. 9. 17. 노동조합과-538 질의·회시 표시). `/decision/` 경로로 열면 '존재하지 않거나 삭제된 페이지'가 뜬다 |
| 하이라이트 조회 `GET /gw/research/api/v3/precedents/{docId}/highlights` | 됨 |
| 결정례·유권해석 하이라이트 저장·삭제(`/v3/decisions/…`, `/v3/interpretations/…`) | 됨(2026. 9. 17. 노동위원회 판정요지와 법제처 회답에 회색으로 시험 저장 → GET 1건 → 화면에서 삭제 → GET 0건). 전문이 PDF 뷰어인 결정례(고용보험심사위원회 재결서)는 선택해도 팔레트가 뜨지 않는다 |
| 본문 선택 → 플로팅 팔레트 표시 | 됨. 색 버튼은 `aria-label="하이라이트 {yellow|green|sky|violet|red|zinc}"` 로 찾는다 |
| 팔레트 색 버튼 실제 클릭 | 됨(2026. 9. 16. KEPS 검토의견에서 판례 5건 7곳 노랑 저장, `GET .../highlights`로 확인). 같은 탭에서 페이지를 옮긴 뒤 스크린샷 안의 화면 배율이 달라져 DOM 좌표 환산값과 실제 표시 위치가 어긋난 적이 있었다. 이때는 배율 1 스크린샷에서 팔레트가 보이는 위치를 클릭한다. 2026. 9. 17. 같은 사건 후속 질의(판례 6건 노랑)에서는 1280×900 에뮬레이션 중에도 배율 1 스크린샷 안의 페이지가 프레임보다 크게 잘려 보일 때, 프레임을 가득 채울 때, 프레임 왼쪽 위 일부에만 작게 그려질 때가 번갈아 나타났다. 여섯 건 중 세 건은 첫 클릭이 빗나갔다. 잘린 화면에서 보이는 위치를 누른 한 건은 DOM 좌표 환산값(`rect × 800 / innerWidth`)으로 다시 눌러 저장되었고, DOM 환산값을 누른 두 건은 배율 1 스크린샷을 새로 찍어 페이지가 작게 그려진 화면에서 보이는 위치를 눌러 저장되었다. 스크린샷을 찍은 뒤 클릭 사이에 표시 상태가 바뀌는 것으로 보이므로, 누를 때마다 GET으로 저장을 확인하고 실패하면 스크린샷을 새로 찍어 다시 누른다 |

팔레트 이름과 작업 색의 대응은 `yellow`=노랑, `green`=연두, `sky`=파랑, `violet`=보라이다.

## 인앱 브라우저의 주의점

- **패널 기본 크기가 작다(좌표 프레임 800×450).** 하이라이트처럼 좌표를 쓰는 작업 전에 `resize_window`로 1280×900 정도로 키운다. 턴이 끝나면 앱이 되돌리므로 다음 턴에 다시 설정한다.
- **Claude 창이 다른 창에 가려 있으면 스크린샷이 시간 초과된다.** 한 번 다시 찍으면 대개 된다. 그래도 실패하면 화면 대신 `get_page_text`·`read_page`로 진행하고, 좌표가 꼭 필요하면 사용자에게 창을 앞으로 가져와 달라고 한다.
- 좌표는 **스크린샷 결과에 적힌 좌표 프레임**을 쓴다. 축소 배율로 찍어도 좌표는 항상 그 프레임 기준이다. 한 작업 안에서 프레임이 다른 스크린샷을 섞지 않는다.

## 외부 엣지 브라우저에서 확인된 것 (2026. 9. 17.)

| 단계 | 상태 |
|---|---|
| Claude in Chrome 확장 연결 | 됨. 확인한 PC에서 연결 브라우저 1개가 잡혔고 엣지 153(`Edg/153`)이었다. 다른 PC는 미확인 |
| 로그인 확인(`GET .../highlights`) | 됨. 200, 인앱에서 칠한 하이라이트가 그대로 조회됨 |
| 검색 API `POST /gw/research/api/v1/search` | 됨. `"사업의 일괄적용에 해당하지 않는 한"` 10건으로 인앱(로그인)과 같다 |
| 판례 본문 수신(`lboxText`) | 됨(2026. 9. 19. 집 PC 엣지 153, 60건을 한 건씩 4초 간격으로 받음, 확인 화면 없음) |
| 목록 검색 대량 | 됨(2026. 9. 19. 하루에 목록 요청 약 7,400회를 요청 사이 1.2초로 보냄, 확인 화면 없음) |
| 원문 열기(`lbox-검색` 3항 블록) | 됨(2026. 9. 19. 판결 1건, 사용량 기록에 들어가고 정상 화면) |
| 본문 선택 → 팔레트 → 색 버튼 실제 클릭 | 됨(2026. 9. 20. 대법원 90누4204에 회색 1곳 저장 → `GET .../highlights` 1건 확인 → 화면에서 삭제 → 0건 확인). 판결 본문이 `innerText`로는 일부만 나오므로 문단은 텍스트 노드(`createTreeWalker`)로 찾는다. `Range` 선택 뒤 `document`에 `mouseup`을 보내면 팔레트가 1초쯤 뒤에 뜨므로, 곧바로 `[aria-label^="하이라이트 "]`를 찾으면 없다. 좌표는 `rect × 1568 / innerWidth` 로 환산해 눌렀다(스크린샷 프레임 1568×756, 페이지 1912×922) |

## 외부 엣지 브라우저의 주의점

- 확장이 만든 작업용 탭 그룹에서 새 탭을 열어 쓰고, 마치면 닫는다. 사용자가 쓰던 탭은 조작하지 않는다.
- **LBOX 화면(검색 결과·판례 상세)의 DOM을 고쳐 쓰지 않는다.** 긴 목록을 읽으려고 `document.body.innerHTML`을 바꾸면 그 순간에는 되지만 곧 화면이 멈춘다. 2026. 9. 20. 변호사 판례검색에서 수확 결과를 LBOX 검색 화면에 출력하다가 렌더러가 두 번 멈췄고, 스크립트·스크린샷이 모두 45초 제한에 걸려 탭을 닫아야 했다. 그때 `window`에 들고 있던 수확 결과(판례 3,271건·추가 3,689건·결정례 1,468건, 요청 460회분)를 잃었다. 탭을 닫아 렌더러를 죽여야 풀리고, 같은 출처의 다른 탭도 함께 느려진다.
- **탭을 둘로 나눈다. 조종 탭과 열람 탭이다.** 조종 탭은 `https://lbox.kr/robots.txt` 처럼 앱이 돌지 않는 같은 출처 페이지를 띄워 두고, 여기에 `lbox-검색` 스킬의 코드 블록과 수확 결과를 두고 출력도 여기에 쓴다(`document.body.innerHTML`을 바꿔도 안전하다). 판례 원문·하이라이트는 열람 탭에서 한다. 한 탭으로 하면 원문을 열 때마다 전역 함수와 수확 결과가 사라져 코드를 다시 붙여야 한다.
- **본문을 받는 중에는 같은 탭에서 화면을 읽지 않는다.** `lboxText`가 요청을 내보내는 동안 `get_page_text`·`read_page`가 '페이지가 아직 로딩 중'으로 45초를 기다리다 실패한다(2026. 9. 20.). 걸어 둔 본문이 끝난 뒤에 읽거나, 조종 탭과 열람 탭을 나눈다.
- **도구로 보내는 코드 안의 한글이 깨질 수 있다.** 2026. 9. 20. `2021구합90220`이 `2021구햩70220`으로, `2013나2012615`가 `2013늘2012615`로 도착해 본문 조회가 '없음', 하이라이트 확인이 '0건'으로 잘못 나왔다. **사건번호·문서 ID는 코드에 직접 적지 말고** 열려 있는 페이지의 `location.pathname`에서 뽑거나(`decodeURIComponent(location.pathname.split('/case/')[1]).replace('/','-')`), 배열에 담아 index로 고르거나, 헷갈리는 글자는 `String.fromCharCode(0xB098)`(나)처럼 만든다.
- **탭이 화면에 보이지 않으면 뷰포트가 줄어든다.** 2026. 9. 20. 엣지 창이 뒤로 갔을 때 `document.visibilityState`가 `hidden`이 되고 `innerWidth`가 1912에서 342로 줄어, 스크린샷이 342×98로 찍혀 좌표 작업을 할 수 없었다. 같은 주소로 `navigate` 하면 되살아난다. 좌표를 쓰기 전에 `innerWidth`를 확인한다.
- **작업용 탭은 화면에 보이지 않는 탭이라 페이지 타이머가 늦춰진다.** 2026. 9. 19. 집 PC 엣지에서 1.2초로 건 타이머가 2초 걸렸고, 요청 사이를 쉬는 스크립트를 기다리던 도구 호출이 45초 제한에 걸려 끊겼다. `lbox-검색` 3항 첫 블록의 `lboxSleep`은 워커 타이머를 함께 써서 1.2초를 지켰다.
- **스크립트 실행 도구는 한 번에 45초쯤에서 끊기고, 끊긴 호출이 끝나지 않으면 뒤의 호출과 스크린샷도 막힌다.** 오래 걸리는 수확·본문 수신은 걸어 두고, 다음 호출에서 결과를 읽는다.
- **엣지가 오래 쓰지 않은 탭을 재우면 도구가 응답하지 않고, 탭 번호가 바뀌며 붙여 둔 함수가 사라질 수 있다**(2026. 9. 19. 20분쯤 손대지 않은 사이 발생). 그때는 `tabs_context`로 탭을 다시 찾고 주소를 다시 열어 깨운 뒤 코드를 다시 붙인다. 긴 작업은 진행 결과를 IndexedDB에 남겨 두어 탭이 새로 열려도 이어 간다. `localStorage`에는 큰 자료를 쌓지 않는다. 본문 사용량 기록(`lbox본문`)과 멈춤 표시가 같은 저장소를 쓰므로, 용량이 차면 그 기록이 쓰이지 않는다.
- **큰 JSON·코드는 손으로 옮겨 적지 않고 파일로 올린다.** 탭에 파일 입력 상자를 만들고 브라우저 도구의 파일 올리기로 넣은 뒤 읽는다(`공통/검증/판례검색/README.md` 4 참조).

## 어느 브라우저에서나 지키는 것

- 공통 스킬의 DOM 선택·좌표·GET 경로는 관찰로 확인한 구현이다. 현재 도구가 허용하고 실제 화면에서 확인된 방식만 쓴다.
- `lbox-검색` 스킬 3항의 검색 API는 2026. 9. 16. 실측으로 확인한 것이다. 브라우저에서 스크립트 실행이 되면 그대로 쓰고, 실패하면 같은 항의 지시대로 화면 조작으로 돌아간다.
- **LBOX가 이용 확인 화면(주소 `/recaptcha`, '자동 수집 방지 확인 절차')을 띄우면 `lbox-검색` 스킬 3항 '이용 확인 화면이 뜨면'에 따라 모든 LBOX 요청을 멈춘다.** 확인 항목은 사용자가 직접 체크하고 클릭·스크립트로 대신 누르지 않는다. 화면 조작이나 다른 브라우저로 옮겨 이어 받지 않는다(2026. 9. 17. 본문 400건 남짓에서 발생, 본문 수신 한도는 같은 항 '계정 보호').
- **여러 세션이 LBOX를 함께 쓸 때에는 같은 브라우저로 모은다.** `lbox-검색` 스킬의 코드는 같은 브라우저 안에서만 세션끼리 요청 차례·본문 사용량·멈춤 표시를 맞춘다(3항 '계정 보호'). 원문 페이지는 `lbox-검색` 스킬 3항 '원문 열기' 블록을 거쳐 연다. 멈춤 표시·본문 한도·간격을 보고 사용량 기록에 넣는다.
- 저장 확인용 GET이 허용되지 않으면 화면의 하이라이트 목록과 재방문으로 확인한다. 확인할 수 없으면 **저장 미확인으로 보고한다.** 성공했다고 적지 않는다.
- 선택·삭제·색상 지정은 화면을 확인하며 수행한다. 하이라이트 전체 삭제를 하지 않고 이번에 인용하는 범위의 기존 표시만 대상으로 한다.
- 서로 다른 에이전트가 같은 브라우저 탭을 동시에 조작하지 않는다.
- 로그인이나 지원되는 조작 수단이 없으면 해당 단계만 미완료로 남기고 원인과 필요한 연결을 알린다.
