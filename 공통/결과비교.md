# GPT·Claude 결과 비교

## 두 모드

- 동일 입력 비교: 같은 과제, 사건 자료, 지침·양식 버전을 고정한 뒤 두 제품이 독립 작성한다. 상대 결과를 읽기 전에 자신의 결과를 확정한다.
- 기존 결과 비교: 두 결과와 실제 사용 자료를 대조한다. 입력·모델·검색 시점이 다르거나 불명확하면 통제된 성능 비교라고 부르지 않는다.

## 동일 입력 묶음

루트에서 실행한다. `--inputs`에는 이번 과제에 필요한 원자료·기존 서면·프레임을 모두 명시한다. 폴더를 주면 그 안의 파일을 포함하며 백업·캐시·비교·작업 폴더는 제외한다. 작업 폴더의 사실관계 정리 등이 필요하면 그 파일을 직접 지정한다. 미지원 형식도 원본을 보존하며 읽을 수 없으면 변환 필요로 표시한다. 입력은 복사하여 고정한다.

```powershell
python 공통/scripts/system.py prepare --case "4_서면작성/사건/사건명" --task "지정 자료에 따라 항소이유서 작성" --inputs "4_서면작성/사건/사건명/라운드4/우리증거" "4_서면작성/사건/사건명/라운드4/출력/서면_프레임.docx"
```

실제 작업에서는 이전 라운드 서면·상대 자료 등 필수 입력도 추가한다. 입력이 부족한 실험으로 모델 능력을 평가하지 않는다. `준비.json`의 `bundle_id`와 `입력목록`이 같아야 동일 묶음이다. `gpt/요청.md`와 `claude/요청.md`의 내용은 같으며 각 제품에 해당 요청을 전달한다. 묶음 `기준/`은 읽기 전용 자료로 취급하고 결과는 각 실행 폴더에 둔다. 제품별 내장 지침·도구가 다르므로 완전히 같은 실행 환경이라고 표기하지 않는다.

모델 호출은 수동 시작이다. 모델·추론 수준을 실제 선택한 값으로 기록한다. 외부 LBOX 검색을 허용하면 검색 시점·검색어·열람 범위도 남긴다. 작성 능력만 비교하려면 동일하게 확보한 판례 원문을 입력에 포함하고 추가 검색 조건을 양쪽에 동일하게 지정한다. 일반 업무의 필수 검색을 생략한 실험은 실무 완성본으로 취급하지 않는다.

## 결과 등록과 대조

```powershell
python 공통/scripts/system.py capture "묶음경로" --provider gpt --result "GPT결과.md" --model "실제 모델명"
python 공통/scripts/system.py capture "묶음경로" --provider claude --result "Claude결과.docx" --model "실제 모델명"
python 공통/scripts/system.py compare "묶음경로"
```

선택 항목은 `--effort`, `--seconds`, `--input-tokens`, `--output-tokens`이다. 제품에서 확인하지 못한 수치는 넣지 않는다. 결과 등록 시 기준 자료 해시를 검사하며, 이미 등록한 결과는 덮어쓰지 않는다. 다시 비교하려면 새 묶음을 만든다. 결과는 MD·TXT·DOCX·PDF를 지원한다. 원본도 보존하고 추출본을 따로 둔다. 이미지·스캔만 있는 결과는 추출 실패/확인 필요로 표시한다.

이미 작성된 결과는 과제에 '기존 결과 사후 비교'라고 쓰고 `prepare --mode retrospective`로 묶는다. 출처 조건이 다르면 그 한계를 비교표에 남긴다.

## 사람이 읽는 평가

`compare`가 만드는 `비교기초.md`와 `문장차이.diff`는 정량·문자 대조이며 법적 평가가 아니다. 검토자는 두 결과 전체와 관련 원문을 읽고 같은 폴더의 `검토결과.md`에 아래를 작성한다. 점수를 기계적으로 부여하거나 인용이 많은 쪽을 우수하다고 판단하지 않는다.

| 항목 | GPT 위치·문구 | Claude 위치·문구 | 원자료·면수·원문 | 판단·수정안 |
|---|---|---|---|---|
| 사실 정확성 | | | | |
| 증거 인용 | | | | |
| 법리·판례 적용 | | | | |
| 불리한 근거·상대 주장 대응 | | | | |
| 이전 입장과 일관성 | | | | |
| 문체·서식 | | | | |

- 각 지적은 원문으로 확인/추론/미확인 중 하나로 구분한다. 불리한 자료와 반박 누락을 포함한다.
- 판례·법령은 LBOX 등 원문 검증을 거친다. 판례가 없는 것으로 결론 내리기 전 기존 검색 절차를 모두 이행한다.
- DOCX·PDF는 추출 텍스트만으로 서식 점수를 내지 말고 해당 문서 스킬의 렌더·시각 검증을 거친다.
- 차이가 없는 문장도 오류일 수 있다. 두 모델이 동의했다는 사실을 검증으로 대체하지 않는다.
- 채택 문장·수정 문장·담당자 확인사항과 실제 수정 부담을 남긴다. 최종 채택본을 요청받으면 별도로 만들고 원래 두 결과를 보존한다.
- 사용량은 서로 다른 제품·요금제·모델의 숫자를 단순 합산하여 비용으로 환산하지 않는다. API 가격과 구독 한도는 구분한다.
